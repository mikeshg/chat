## 2. 接口契约

### 表

`users.agent_access boolean NULL`。NULL = 跟随全局默认。

`server_settings` 不加列。键：

| key | jsonb | 缺键 |
|---|---|---|
| `agent_enabled` | bool | `true` |
| `agent_default_allowed` | bool | `true` |

任务单写成列上的 `boolean NOT NULL DEFAULT true`。现有 `server_settings` 是 key/jsonb，任务单也要求沿用这套存取、不进 `Config`。语义与「缺省 true」一致。

生效：管理员 → 可用；否则 `agent_enabled=false` → 不可用；否则 `users.agent_access` 非 NULL 用它，否则用 `agent_default_allowed`。

### REST

- `GET/PUT /v1/admin/settings` 增加 `agent_enabled`、`agent_default_allowed`。PUT 仍是部分更新。
- `PUT /v1/admin/users/{id}/agent-access`，body `{ "allowed": true | false | null }`。204。用户不存在 404。
- `GET /v1/admin/users` 每条增加 `agent_access`（覆盖，null 为跟随默认）和 `agent_access_effective`。
- `GET /v1/users/me` 以及登录、刷新、改密、改昵称、换头像返回的当前用户增加 `agent_access: bool`（生效值）。别人的 `UserPublic` 不带这个字段。
- 无权时这些接口 403 `{"error":"agent_access_denied"}`：宿主列表、Agent 增删改查、头像 PUT、probe、个人设置、调用历史、取消、上下文重置。头像 GET 仍不鉴权。
- 专属会话发消息走 WS，错误帧 `code` / `message` 都是 `agent_access_denied`，消息不落库。同一 `PostError` 若从 REST 转发进入专属会话，`post_err` 把它映射成 HTTP 400，正文同样是 `agent_access_denied`。群/私聊里的 @ 只是不产生调用，消息照常保存。

### WS

- 使用权变化时给该用户推 `{"type":"invalidate","what":"me"}`。前端重拉 `/users/me`，桌面端据此停或启动宿主。
- 收回时：`agent_invocation` 帧 `status=cancelled`、`error=agent_access_revoked`；宿主收到 `invocation_cancel` 后连接被关，主人收到 `agent_host_status online=false`。
- 宿主登记记住 ticket 的 `sid`。禁用（全部）、移出某个登录会话（该会话的宿主）、改密（除当前会话外）、恢复备份（全部，含只有宿主没有普通连接的用户）都走原有 `kick_*`。

降权后若生效值从有变无，同样收回并推 `invalidate me`。任务单点名的是开关、默认、覆盖和禁用；降权不处理的话，管理员被撤成普通用户后全局关着仍会留着宿主和进行中的调用。
