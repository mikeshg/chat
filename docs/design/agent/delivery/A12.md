## 2. 接口契约

迁移 `0028_agent_approvals.sql`。

`agents.permission_tier text NOT NULL DEFAULT 'read_only'`，取值 `read_only` / `workspace` / `full`。

`agent_approvals`：`id`、`invocation_id → agent_invocations ON DELETE CASCADE`、`message_id → messages ON DELETE CASCADE`、`request jsonb`、`options jsonb`、`status`（`pending` / `decided` / `expired`）、`decision text NULL`、`decided_at`、`created_at`。

`request` 除任务单里的 `title`、`kind`、`locations`、精简 `tool_call` 外，还存了 `request_id` 和 `invocation_id`。前者用来把决定送回这次等待，后者让专属会话里的「去审批」滚到对应卡片。

`POST /v1/agents` 接受可选 `permission_tier`，缺省 `read_only`。非法值 `400 bad_permission_tier`。创建表单要能选档位，所以创建接口也收下这个字段。

`PATCH /v1/agents/{id}` 接受可选 `permission_tier`，缺省不改。`AgentView` 始终带 `permission_tier`。

`invocation_start` 的 `agent` 快照增加 `permission_tier`。旧快照没有该字段时宿主按只读。

宿主 → 服务端：

```json
{"type":"approval_request","invocation_id":"...","request_id":"...","tool_call":{"title":"...","kind":"edit","locations":["..."]},"options":[{"optionId":"allow","name":"...","kind":"allow_once"}]}
```

服务端 → 宿主：

```json
{"type":"approval_decision","request_id":"...","option_id":"allow"}
```

`POST /v1/agent-approvals/{id}/decide`，body `{ "option_id": "..." }`。

- 不是该 Agent 主人，或审批不存在：`404 {"error":"approval not found"}`
- 不是 `pending`，或调用已不是 `awaiting_approval`：`409 {"error":"not_pending"}`
- `option_id` 不在选项里：`400 {"error":"bad_option"}`
- 成功：`200`，body 是更新后的 `MessageView`。审批变为 `decided`，调用回到 `running`，原会话成员收到 `agent_invocation`，卡片所在会话收到 `message_updated`，宿主收到 `approval_decision`。

卡片消息 `kind='approval'`，只写进该 Agent 的专属会话，作者是 Agent。正文是可读摘要，例如「请求写入：C:/outside/a12secret.txt」。`MessageView.approval` 为 `{ id, status, request, options, decision }`，没有审批时省略该字段。

决定或失效时给卡片消息的 `edit_version` +1（不写 `edited_at`，界面不会显示「已编辑」），再推 `message_updated`。现有客户端按版本合并，同版本更新会被丢掉，所以必须抬版本。

调用被取消、失败、宿主断开、删除 Agent、收回使用权时，该调用上仍为 `pending` 的审批改为 `expired`，并同样推 `message_updated`。

原会话（群 / 私聊）只收到 `agent_invocation.status = awaiting_approval`，不收到卡片消息。

档位：

- `read_only`：`read` / `search` / `think` / `fetch` 自动放行。
- `workspace`：在只读基础上，`edit` / `delete` / `move` 且每个 location 都在工作目录或额外目录内才自动放行。空路径或有一个在外面，走审批。`execute` 一律走审批。
- `full`：全部自动放行。

自动放行选 `kind=allow_once` 的选项；没有则选第一个 `kind` 含 `allow` 的选项。假 agent 的选项是 `allow`（`allow_once`）/ `always`（`allow_always`）/ `reject`（`reject_once`）。

## 4. 未覆盖项与已知限制

- 没有用 ACP 会话模式表达档位。各 agent 的模式名字不统一，任务单明确先不做。
- 「往其他会话发消息」的档位控制留给 A16。
- 「总是允许」只把 `allow_always` 的 `optionId` 原样交给 agent，服务端不记持久规则。
- 相对路径按工作目录拼接后再判断是否越界；路径不要求已经存在于磁盘上。
- 审批等待没有单独超时。一直不决定就一直停在 `awaiting_approval`，直到主人决定、取消或宿主断开。
- 创建表单的档位说明在弹层下半部，桌面截图 `a12-tier.png` 没滚到那一行；脚本确认了说明文字在页面上。
