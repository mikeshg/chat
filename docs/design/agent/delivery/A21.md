接收者重算（退群 / 踢人 / 解散）保持原样。开新话题改成数据库里的代次，不再用进程内闸门。

### 行为

- 进行中调用的 `agent_stream` / 步骤状态帧，在退群、踢人、解散（含最后一人退出并删除会话）提交后，接收者重算为「调用会话当前成员 ∪ 根会话当前成员」。`push_stream` 不查库。
- 重置前派发的调用，成功结束时带了 `session_id` 也不写回。重置后派发的调用照常写回；同一代次上后提交的覆盖先提交的。
- 专属会话只动那个 Agent、键为会话 id 的一行。私聊 / 群只动请求者自己的 Agent。`schedule:<id>` 和子调用的 `call:<id>` 不是这些键，重置碰不到。重置后的空会话留在表里（`runtime_session_id = ''`），不再删行。

## 4. 未覆盖项与已知限制

- `context_epoch` 为 `NULL` 的老调用完成时仍无条件写回。只影响这次迁移上线时已经派发出去、还没结束的调用。
- 排队调用在真正下发 `invocation_start` 时才读代次、才写入 `context_epoch`，不是在插入 `queued` 行的时候。
- 记下代次的 `UPDATE` 若失败，只打日志，调用仍会下发。这样的行 `context_epoch` 仍是 `NULL`，完成时会按老行为写回。
- 流式帧大约每 200ms 一次。成员变更提交到 `refresh_run_members` 返回之前，已经在推的那一帧仍可能用旧名单。
- 调用进行中把人拉进群，不会把新人补进接收者。任务单只要求移出后重算。

### 为什么没有竞态

代次在 `agent_contexts` 行上，派发时抄到 `agent_invocations.context_epoch`。三条语句各自原子，中间没有进程内锁：

1. **派发读**：`SELECT runtime_session_id, epoch`。没有行当成会话空、代次 0；空串会话当成没有。一条语句要么看见重置提交前的行，要么看见提交后的行，不会拆开。
2. **重置**：一条 upsert。没有行就插入 `('', epoch = 1)`；有行就把会话清成 `''` 且 `epoch = epoch + 1`。
3. **完成写回**：`INSERT ... ON CONFLICT DO UPDATE SET runtime_session_id = ..., updated_at = now() WHERE agent_contexts.epoch = 调用行上的 context_epoch`。条件不成立时更新被跳过，已有行保持原样，语句本身不报错。这一句不改 `epoch`。

调用行上的代次是派发读到的那个数，在下发 `invocation_start` 之前用单独的 `UPDATE` 写上（自动提交）。宿主要收到 start 才会 finish，所以正常完成读到的是已经写好的代次。`handle_finish` 用 `FOR UPDATE` 锁调用行，代次就从这行读，不看 `inv_runs`。重启后内存快照没了也一样。

读、重置、写回的交错：

- **读在重置之前**（读到代次 E，会话可能是旧的）。start 可能带上这次读到的旧会话。重置把上下文变成 E+1（原先没有行则是 1）并清空会话。完成时 `WHERE epoch = E` 对不上，不写回。若完成的插入抢在重置提交之前：完成先插入 `(会话, epoch = E)`，重置的 upsert 再把它清掉并把代次加一。两种顺序下来，重置后的表里都没有这个旧会话。
- **重置在读之前**。读到空会话和新代次，start 不带旧会话，调用行记下这个新代次。完成时 `WHERE` 相等，写回新会话。之后若没有新的重置，下一次读得到它。
- **读和重置抢同一条还不存在的行**。读的语句若没看见重置，得到代次 0。重置插入代次 1。完成按 0 去写，冲突后条件失败。若完成的插入先提交，重置随后把该行清掉并升到 1。旧会话留不下来。
- **同一代次的两次完成**。两次 `WHERE` 都通过，行锁把两次更新排开，后提交的 `runtime_session_id` 覆盖先提交的。完成不增加代次。
- **重置前的完成和重置后的完成**。前者的代次对不上，更新被跳过；后者对得上，写自己的会话。谁先提交都一样，前者改不到已经升代的行。
- **两次重置**。每次加一。只看过第一次的调用对不上第二次；读发生在第二次之后的调用对得上。
- **定时调用 / 子调用**。键是 `schedule:<id>` 或 `call:<id>`，和会话 id 不是同一行。重置会话碰不到它们，完成写回也不互相覆盖。

`context_epoch` 为 `NULL` 的老调用不走 `WHERE`，这是迁移兼容，不是上面这条新路径。
