## 2. 接口契约

### WS

`send_message` 增加可选字段：

```json
{ "type": "send_message", "agent_targets": ["<agent uuid>", "..."] }
```

缺省或空数组与旧客户端一样。非法 uuid 整帧视为坏帧。不属于发送者、已删除、重复的 id 忽略，不报错。

`agent_invocation` 帧形状不变，接收者从「只推主人」改为该会话全部成员。取消接口仍是 `POST /v1/agent-invocations/{id}/cancel`，非主人 404。

### REST / 表

无新路由、无新表、无新迁移。`GET /v1/conversations/{id}/agent-invocations` 仍只校验成员。

Agent 回复仍是普通消息，`agent` 字段标识作者，`sender_id` 是主人。可以写进主人仍是成员的私聊、群或专属会话。已删除 Agent 的专属会话仍只读。

### 与任务单的差别

私聊 / 群发给 Agent 的 prompt 会去掉用来点名的 `@名字` 及紧跟的一个空格，这样 `@bot echo:hi` 的指令是 `echo:hi`，`@bot recall` 的指令是 `recall`。剥完只剩空白时退回原文。专属会话仍用全文。任务单没有写 prompt 文本，这是为了和假 ACP agent 的 `echo:` / `recall` 以及「指令本身」对齐。

## 4. 未覆盖项与已知限制

- 主人想 @ 同名群成员时，服务端无法区分：手打 `@token` 先匹配自己未删除的 Agent。补全里点成员时，客户端纯函数会把它当成成员、不放进 `agent_targets`，但正文里仍有 `@名字`，服务端还是会调用 Agent，并且不写入该成员提及。这是任务单写明的已知限制。
- 未读：Agent 回复对每个成员 +1，包括主人。主人的触发消息已经推进自己的已读，所以测完主人未读是 1；另一成员没读触发消息，未读是 2（触发消息 + 回复）。
- 只读私聊发不出消息，因此不会调用；沿用原有 DM 只读校验，没有单独再测一遍。
- 文件传输助手不触发。带附件的消息 `kind` 不是 `text` 时也不触发（与专属会话原行为一致）。
- 审批在群里的呈现（A12）、子调用（A14）、别人调用我的 Agent：未做。
- 调用成功后状态行仍不显示文案（回复消息本身就是结果），与 A01/A04 一致。排队、运行中、失败、取消、超时会显示。
- 没有启动 Tauri 窗口。桌面壳只做了 `cargo check`。
