# A24 交付：宿主连接复核登录会话

宿主 WS 连接补齐登录会话复核：登记后立刻一次（堵住「升级后、hello 前」的撤销缝隙），
读循环里每个 ping 周期一次。复核 SQL 与普通连接共用 `auth::grant_valid`，没有复制。

## 1. 实现摘要

- `server/src/auth.rs`：新增 `grant_valid(pool, uid, session_version, sid)`——账号未禁用、
  `session_version` 一致、`sid` 对应会话未撤销（`sid=None` 不查会话）。`unwrap_or(false)`，
  查询失败一律按无效处理。
- `server/src/ws.rs`：`ws_handler` 升级前复核与 `connection_valid`（登记后 + 每帧）改用
  `grant_valid`，删掉两处重复 SQL；`connection_valid` 仍附加 `conn_alive`（连接表在册校验）。
- `server/src/host_ws.rs`：`register_host` 之后立刻 `grant_valid` 复核；不过则
  `unregister_host` + 发 Close 返回，不发 `host_ready`、不 `flush_queued`、不广播上线。
  读循环 `ping.tick()` 分支里复核一次（不逐帧查库），失败发 Close 后 `break`，
  走既有离线收尾（`unregister_host` → `broadcast_status(false)` → `fail_running`）。
- `server/tests/it.rs`：末尾追加 `// ===== Agent A24 =====` 分节，两个测试 +
  `a24_pending_host` / `a24_until_close` 两个 helper。
- 无迁移、无 REST/WS 协议变更、无前端改动。

## 2. 接口契约

REST、WS 帧、表结构均无新增/变更。行为变更：

- 宿主连接在 `register_host` 后被发现会话失效时，客户端只收到 WS Close（不发
  `force_logout`、不发 `host_ready`），与 `ws.rs` 每帧复核失败的关闭方式一致。
- 已登记宿主的会话失效（撤销/禁用/改密）时，最迟在下一个 ping 周期断开；
  断开按正常离线处理：摘登记、推 `agent_host_status(online=false)`、
  running/awaiting_approval 置 `failed/host_disconnected`，queued 保持排队。
- 复核不过的连接曾顶掉旧连接时，`unregister_host` 按 `conn_id` 校验不会误摘新登记；
  该宿主此后离线，合法客户端换新凭据可重连。

## 4. 未覆盖项与已知限制

- 已登记宿主的复核粒度是一个 ping 周期（`ws_ping_interval_ms`，默认 30s），比
  `kick_session` 的主动断开慢；任务单明确不逐帧查库（流式事件约 100ms/帧）。
  `kick_session`/`kick_other_sessions`/`disconnect_hosts` 的主动断开路径不受影响，
  复核只是兜底。
- hello 前的 upsert 仍会写 `agent_hosts` 行（`install_id` 是永久标识）；复核不过的连接
  只是不登记在线，宿主行保留且 `online=false`。
- `sid=None` 的老宿主连接不查 `sessions`，由 `session_version` 兜底——与普通连接一致。
- 复核失败只发 WS Close，不发 `force_logout` 文本帧（与 `ws.rs` 每帧复核失败一致）。
  宿主端重连需先换 ticket，而 access token 已失效，会在升级前被拒。

## 5. 发现的其他问题（范围外）

- `kick_session`/`disconnect_hosts` 只遍历 `hosts` 表里已登记的连接，升级中未登记的
  连接天然漏网；普通连接在 `conns` 同理。本票按任务单用登记后复核兜住宿主侧；
  普通连接侧已有 `register_conn` 后复核，同样覆盖。
- 宿主掉线补发与取消竞态属 A23，未动。
