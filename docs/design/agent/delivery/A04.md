## 2. 接口契约

### 表

`agent_invocations.queue_deadline timestamptz NULL`。不进入 REST / WS 的 `InvocationView`：客户端只展示状态，不展示截止时间。任务单只要求加列。

### REST

`POST /v1/agent-invocations/{id}/cancel`（无请求体）

- 200：更新后的 `InvocationView`（`status=cancelled`）
- 404：调用不存在，或调用者不是该 Agent 的主人（`{"error":"invocation not found"}`）
- 409：已是 `succeeded` / `failed` / `cancelled` / `timed_out`（`{"error":"already_finished"}`）

`queued` 只改状态。`running` 与 `awaiting_approval` 改状态后向宿主发取消帧。同一用户的其他连接靠 `agent_invocation` 帧同步。

### WS

服务端 → 宿主：`{"type":"invocation_cancel","invocation_id":"<uuid>"}`。

宿主 → 服务端：取消之后的 `invocation_finish` 一律忽略（状态已不是 `running`），不写 Agent 回复。

派发：宿主离线时 `agent_invocation.status=queued`（`error` 为空，`queue_deadline` 不在帧里）。上线后按 `created_at` 先推 `running` 再下发 `invocation_start`，prompt 仍是触发消息正文。

### 宿主

`RunRequest.cancel: watch::Receiver<bool>`。置真后 ACP 发 `{"jsonrpc":"2.0","method":"session/cancel","params":{"sessionId": …}}`，最多等 5 秒，然后杀子进程，且不发 `invocation_finish`。

- `queue_deadline` 不在 API 响应里。
