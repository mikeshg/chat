# A19 交付：宿主路径安全（附件落盘名 + workspace 档真实路径）

## 1. 实现摘要

本票只改 `agent-host/`，无迁移。

- `agent-host/src/files.rs`：
  - `safe_name` 重写为「清洗成单个普通文件名」：取 basename 后剥掉开头盘符前缀（`C:foo.txt` → `foo.txt`）、冒号（含 NTFS 备用数据流写法，`a:stream` → `stream`）、Windows 非法字符 `< > : " | ? * / \` 与控制字符、结尾的点和空格；Windows 保留设备名（`CON`/`PRN`/`AUX`/`NUL`/`COM1-9`/`LPT1-9`，含 `nul.txt` 这类带扩展名的，按首个 `.` 前词干判断、大小写不敏感）加 `_` 前缀；剥空退回附件 id。
  - `download_inputs` 每个附件落到 `in/<附件 id>/<清洗后文件名>`（先建子目录），同名附件不再互相覆盖；`LocalFile.name` 仍是清洗后的可读名，继续用于 ACP `resource_link.name`。
  - 兜底断言：落盘路径的父目录必须正好是 `in/<附件 id>`，否则跳过该附件并 `tracing::warn`。
- `agent-host/src/permission.rs`：`path_inside` 从词法归一改为真实路径判断——roots 先 `canonicalize`（解析失败的根跳过）；loc（相对路径相对 roots[0]）不做词法 `..` 归一，逐组件向前探最长的已存在前缀后 `canonicalize`，再接上剩余不存在的部分；剩余部分含 `..` 等非普通组件判为不在目录内（交主人审批）。前缀边界规则不变（`Path::starts_with` 组件级比较，`C:\workspace` 不是 `C:\work` 的子路径）。删除不再使用的 `logical_norm`。
  - 探测用**前向逐组件**而非反向 `pop`：实测 Windows 的 `Path::exists()` 对「不存在目录 + `..`」也返回真（`work\newdir\..` 判存在），反向会把 `..` 吞进前缀导致误判放行。
  - 裸盘符前缀组件（`C:` 或 `\\?\C:`）不是可探测实体，直接种下不计入存在性检查。
  - 单测全部改为真实临时目录树（`work`/`extra`/`outside`/`workspace` 兄弟目录），新增 junction（`cmd /C mklink /J`，Unix 用 `std::os::unix::fs::symlink`，建不出来打印原因跳过）指向目录外不放行、指向目录内放行、新文件按已存在祖先判断、`新目录/../x` 剩余部分含 `..` 不放行、解析失败的根跳过等用例。
- `agent-host/tests/files.rs`：追加 `// ===== Agent A19 =====` 两条用例——对抗文件名（`C:foo.txt`/`..\..\x`/`a/b/c.txt`/`nul.txt`/`a:stream`/空名，全部落在 `in/<id>/` 下且名字无非法字符）与同名附件互不覆盖（两份都在、内容各自正确）。

## 2. 接口契约

无对外接口变更。`agent-host` 内部行为变化：

- `download_inputs` 的 `LocalFile.path` 从 `in/<basename>` 改为 `in/<附件 id>/<清洗后文件名>`；`LocalFile.name` 语义不变（可读名）。
- `path_inside` 签名不变，判断从词法变为真实路径；`within_tier` / `summarize_tool` / `location_strings` 等公开接口均未变。调用方 `acp.rs` 的 `permission_roots` 无需改动（roots 在 `path_inside` 内 canonicalize）。

与任务单的偏差：无。

## 4. 未覆盖项与已知限制

- `path_inside` 的判定是 TOCTOU 的：判定通过到 Agent 真正写文件之间，目录可能被换成链接。任务是「防误操作的护栏，不是沙箱」（任务单背景），此窗口接受。
- 已存在前缀里经真实目录的 `..`（如 `work\sub\..\f`）由 canonicalize 解析为 `work\f`，按落点放行——这是真实语义；只有落在不存在目录之后的 `..` 才拒绝。
- `path_inside` 每次调用对每个 root 做一次 `canonicalize`、对 loc 每组件做一次 `exists()`。审批路径低频，不做缓存。
- loc 为盘符相对路径（`C:foo`）时 join 语义下按「C 盘进程当前目录」解析，判定结果取决于宿主 cwd——与旧行为一致，未额外处理。
- 保留设备名仅覆盖 `CON/PRN/AUX/NUL/COM1-9/LPT1-9`；`CONIN$`、`COM¹` 这类冷门写法未覆盖（命中它们的附件写失败走既有跳过路径，不写出 `in/`）。
- 服务端不清洗上传文件名、MCP `send_message` 的 `file_paths` 相对路径基准——按任务单「不做」范围未动。
