# A20 交付：发消息审批完整披露正文与附件

对应 `docs/design/agent/tasks/A20-send-approval-disclosure.md`。本票没有迁移。

## 1. 实现摘要

- `agent-host/src/mcp.rs`：只读档 `send_message` 在发起审批前先校验展示上限（正文 ≤4000 字、`file_paths` ≤20 条、单条绝对路径 ≤500 字），超限直接给 Agent 返回错误，不发审批、不上传、不查会话。`file_paths` 经 `std::path::absolute` 转成与 `upload_local` 读取基准一致的绝对路径后写进审批 `tool_call.locations`；完整正文写进新字段 `tool_call.detail`。批准后上传的就是已展示的这份清单（同一个 `Vec`，不重解析参数）。`await_send_approval` 改为接收 `detail` + `locations` 组装 `tool_call`。`workspace` / `full` 档行为不变。
- `server/src/approvals.rs`：`sanitize_request` 保留 `tool_call.detail`（按字截到 4000，与消息正文上限一致），写进 `request.detail` 和内嵌 `request.tool_call.detail`。
- `app/src/types.ts`：`ApprovalRequest` 增加可选 `detail`（旧服务端缺省）。
- `app/src/ui/ApprovalCard.tsx`：`detail` 非空时在卡片里用 `<details open><pre>` 全文展示（保留换行，可折叠、不丢内容）。
- `app/src/styles.css`：末尾 `/* ===== Agent A20 ===== */`，`.approval-detail` 的 summary / pre 样式（用 CSS 变量，pre 限高滚动）。
- `agent-host/tests/mcp.rs`：末尾 `// ===== Agent A20 =====`，2 个新测试 + `fake_send_upload_backend`（含 multipart 上传的假后端）。
- `server/tests/it.rs`：末尾 `// ===== Agent A20 =====`，`a20_raw_host` 裸宿主连接（role=host）直发 `approval_request`，测 detail 保留与截断。
- `app/src/ui/ApprovalCard.test.tsx`：新文件，3 个 vitest 渲染断言。

## 2. 接口契约

### WS（宿主 → 服务端）

`approval_request` 帧的 `tool_call` 增加可选字段：

```json
{ "type": "approval_request", "invocation_id": "…", "request_id": "…",
  "tool_call": { "title": "…", "kind": "send_message",
                 "locations": ["C:\\abs\\a.txt"], "detail": "<完整正文>" },
  "options": [ … ] }
```

`detail` ≤4000 字（服务端按字截断兜底）；`locations` 语义不变（≤20 条、每条 ≤500 字）。宿主只读档 `send_message` 现在发的 `locations` 是 `std::path::absolute` 绝对路径（原来是固定 `[]`）。`detail` 同时出现在落库后的 `approval.request` 和 `request.tool_call` 里。旧宿主不带 `detail` → 存成 `""`，旧客户端忽略该字段。

### REST / 表

无新路由、无新表、无新迁移。`agent_approvals.request`（jsonb）里多了 `detail` 键。

### 与任务单的差别

无。标题仍保留 `发消息到「会话」：` + 前 80 字预览作卡片标题；完整内容在 `detail`。

## 4. 未覆盖项与已知限制

- 任务单「不做」列出的：`file_paths` 相对路径的解析基准仍是宿主进程当前目录（与 `upload_local` 一致，审批展示路径即实际读取路径；如需改成 Agent 工作目录另议，见第 5 节）。
- 非 UTF-8 路径在只读档下会直接报错（无法在卡片上如实展示的路径不允许批准）；`workspace`/`full` 档不受此限，与原行为一致。
- ACP 侧 `session/request_permission` 的审批（`acp.rs` 的 `perm:` 路径）`tool_call` 不带 `detail`，服务端存 `""`、前端不渲染正文区——本票只覆盖 `send_message` 工具，符合任务单范围。
- 任务单未要求浏览器实测（检查节只列 devin-rules §4 四项），未跑无头 Playwright。
- 并发审批是 A22，本票未动。

## 5. 发现的其他问题（范围外，只记录）

- `file_paths` 的相对路径按宿主进程当前目录解析，而不是 Agent 的工作目录（`spec.cwd` / `data_dir`）：Agent 在别的工作目录下传相对路径时，读到的是宿主 CWD 下的文件。展示与读取现在是一致的（同一基准），但基准本身可能与 Agent 预期不符——任务单已列为「另议」。
- `cargo check`（`app/src-tauri`）过程中 tauri build 脚本触碰了 `gen/schemas/{desktop,windows}-schema.json` 的 mtime，`git status` 显示 M，但 `git diff` 为空（内容与 HEAD 完全一致）。
