# A26 Agent 管理页重做

用户反馈现在的 Agent 配置「过于难以使用」：编辑表单太长、添加流程不清楚、列表看不清、弹窗太挤。已和用户定下方案并确认草图。先读 [../devin-rules.md](../devin-rules.md)、`CONTEXT.md` 的「Agent」小节，再**用浏览器打开草图 [../mockups/agent-manager.html](../mockups/agent-manager.html) 逐个点一遍**（桌面 / 手机两种预览都看），实现以草图为准。本票没有迁移。

## 用户的决定

1. 左侧导航新增「Agent」一级入口，与会话、联系人、我平级（`canUseAgent(me)` 为假时不显示）；「我」页里原来的 Agent 入口和 `AgentsPanel` 弹窗去掉。
2. 整页主从布局：左栏列表，右栏详情。窄屏（≤720px，含 Android）变成「列表 → 详情」两级，详情页左上角「← 返回」。
3. **只能在桌面端添加 Agent，而且只加到本机。** 手机 / 网页只能管理和调用已有的 Agent。
4. 界面上的「宿主」统一改叫「电脑」（所有用户可见文案，含会话、审批、设置等处；代码标识符不改）。
5. 添加流程：一页逐步展开——先选程序，选好后下面才出现名字、工作目录、权限。**选程序处加搜索框**（按名字 / id 过滤登记表条目，自定义命令卡片始终显示）。

## 页面（对照草图）

### 左栏

- 标题「Agent」，右侧「＋ 添加」：只在桌面端、且本机这台电脑在线时显示。
- 按电脑分组：在线圆点、电脑名、桌面端给本机加「本机」标签、系统；**离线时才显示「最后在线 …」**。电脑名右侧「⋯」菜单里是「改名」，行内编辑。
- 组内每个 Agent 一行：头像、名字、`程序名 · 权限档位`、电脑在线状态点。点击打开右栏详情。空组显示「这台电脑上还没有 Agent」。
- 底部「⚙ 默认设置」打开右栏的默认设置。手机 / 网页在底部说明「要添加 Agent，在想让它运行的那台电脑上打开 Chat 桌面端」。

### 右栏：Agent 详情

- 头部：头像、名字、`运行在 X（本机）· 在线 / 离线，新调用会排队`，右侧「进入会话 →」（打开专属会话，沿用现在 `openAgentConv` 的做法）。
- 5 个标签，字段归属照草图：
  - 基本：头像（点击更换）、名字（下方提示 `@名字` 调用和命名规则）、运行在（只读，说明不能换电脑）、删除（危险区，页内二次确认，不用 `window.confirm`）。
  - 程序：登记表程序只读显示名称和版本；自定义命令可改命令和参数（每行一个）；模型 / 模式下拉（来自上报的可选项，旁边「重新读取」走现有 probe）；附加指令；环境变量放在可折叠区，写明明文存服务器。
  - 权限：工作目录、额外目录（逐行增删）、权限档位做成带说明的单选卡片（文案用 `approval.ts` 的 `PERMISSION_TIERS`）。
  - 回复：输出方式单选卡片，第一项「跟随默认设置（现在是 X）」；离线排队下拉，第一项「跟随默认设置（现在是 X）」。
  - 定时任务：复用 `AgentSchedules` 的逻辑，样式对齐新页面；启用 / 删除 / 新建即时生效（和现在一样）。
- 前四个标签共用一份草稿：任何改动后底部出现保存条「有未保存的修改 [放弃] [保存]」，一次 PATCH 保存全部（沿用 `shapeAgentPatch`）。有未保存修改时切换 Agent、打开添加或默认设置，要页内确认是否放弃。
- 服务端错误文案沿用 `AgentEditor.tsx` 的 `errText` 映射。

### 右栏：添加 Agent（仅桌面端）

- 头部写明「运行在这台电脑：X（系统）」，不让选电脑。
- 第 1 步：搜索框 + 程序卡片（登记表条目，按本机查询）：可用 / 需安装（卡片下方就地安装，显示进度，沿用 `RegistryPicker` 的安装流程和 WS 进度帧）/ 不可用（灰掉并显示原因）；最后一张「自定义命令」。
- 选好后展开第 2 步：自定义命令时先填命令和参数；名字（按程序预填，可改）、工作目录（可留空）、权限档位卡片（默认只读）。「创建 Agent」后直接打开它的详情页，并提示「已创建，去专属会话发条消息试试」。

### 右栏：默认设置

输出方式（单选卡片）、离线排队多久后取消、Agent 互相调用最多几层（附一句解释）。改动即时保存。

## 本机识别与服务端强制

1. 前端要知道「本机」是哪台电脑：桌面端（Tauri）从宿主运行时拿到本机的 host id（宿主就绪后才有；需要时在 `app/src-tauri` 加一个命令或事件，桌面端 `agentHost.ts` 接过来放进 store）。拿不到（网页、Android、宿主还没就绪）就视为没有本机，不显示「添加」。
2. 服务端 `POST /v1/agents`：目标电脑必须当前在线，且它的宿主连接所属登录会话（`HostConn.sid`）等于这次请求的登录会话；否则 403 `host_not_local`（请求 token 没有 sid 也拒绝）。前端把这个错误显示成「只能添加到正在运行 Chat 桌面端的这台电脑」。编辑、删除、探测、定时任务等其他接口不变。

## 文档

- `README.md`「Agent」一节：添加方式改为「在桌面端上添加，只加到这台电脑；手机和网页可以管理、调用已有的 Agent」；「宿主」的说法改成「电脑」。
- `CONTEXT.md`：补一条添加规则（只能在那台电脑的桌面端上添加）；领域词 `AgentHost` 可保留，但注明界面上叫「电脑」。

## 测试

- server `it.rs`：本机会话添加成功；另一个会话（同一用户、不同登录）向这台电脑添加 → 403 `host_not_local`；电脑离线 → 403。现有创建 Agent 的测试按新规则调整（用宿主连接所在的会话发请求）。
- vitest：列表分组与状态文案（离线才显示最后在线、本机标签）、搜索过滤、草稿脏标记与保存条、默认设置「跟随默认（现在是 X）」的文案。纯函数放 `.ts` 里测，沿用现有 `agentHosts.test.ts` / `agentForm.test.ts` 的写法。
- 无头 Playwright：起槽位后端，托管 `app/dist`，用 1280×800 和 390×844 两种尺寸截图——列表 + 详情每个标签、默认设置、手机的列表和详情。添加页在浏览器里没有本机，可以在测试页里注入一个本机 host id 来截图。截图存到 `server/target/wt/shots/`，文件名写进交付文档。
