# P1-3 按会话保留草稿 + 暗色模式 — 交付文档

## 1. 实现摘要

只改客户端（`app/`），服务端、迁移、依赖零改动。

新增文件：

- `app/src/drafts.ts` — 草稿持久化纯函数：`chat_drafts:<userId>` localStorage 读写，读写吞异常，损坏/非对象 JSON 按 `{}` 处理，只保留非空字符串值。
- `app/src/theme.ts` — 主题纯函数：`chat_theme` 读取（非法/缺失按 `system`）、`system|light|dark` → `data-theme` 映射、`applyTheme()` 落/删 `<html data-theme>`。
- `app/src/ui/convPreview.ts` — 会话列表副标题纯函数：typing > 草稿（非当前会话，取首行）> 最后一条消息 > 「暂无消息」。
- `app/src/ui/ThemeSetting.tsx` — 「外观」独立设置组件：跟随系统/浅色/深色单选，写入 `chat_theme` 并立即 `applyTheme`。
- `app/src/drafts.test.ts` / `app/src/theme.test.ts` / `app/src/ui/convPreview.test.ts` — 16 个新单测。

修改文件：

- `app/src/store.ts` — `AppState` 加 `drafts` 字段；`setDraft(convId, text)`（空串删键）+ 300ms 防抖 `writeDrafts`；`flushDrafts()` 立即落盘。
- `app/src/ui/ChatView.tsx` — 输入/自动补全走 `setDraft`（编辑态除外）；会话切换时把旧会话草稿落库（编辑态取 `draftBeforeEdit`）并从 `drafts` 恢复新会话文本；发送即 `setDraft(id, "")`。
- `app/src/ui/ConvList.tsx` — 副标题改用 `convPreview`；`kind==="draft"` 时渲染 `<span class="draft-tag">[草稿]</span>`，`[有人@我]` 仍在其前。
- `app/src/ui/AuthScreen.tsx` — 登录/注册成功后 `readDrafts(localStorage, me.id)` 进 state。
- `app/src/App.tsx` — 启动 `auth.me()` 后加载草稿；`chat:logout` 时先 `flushDrafts()` 再把内存 `drafts` 清 `{}`（localStorage 保留）。
- `app/src/main.tsx` — React 渲染前 `applyTheme(readThemeChoice(...))` 防白闪；`pagehide` 时 `flushDrafts()` 堵防抖窗口。
- `app/src/ui/MePanel.tsx` — 一行挂载 `<ThemeSetting />`，位于「连接」卡片之前。
- `app/src/styles.css` — `:root` 变量用 `light-dark(浅,深)` 收编全部写死颜色（见 §4 说明）；新增 `--hover/--selected/--input-bg/--avatar-*/--link/--link-mine/--mention-*/--warn-*/--chip-me-bg/--quote-bg/--overlay/--shadow*/--code-bg/--code-fg/--dot-off/--auth-bg-*/--bubble-*`；`--bubble-mine` 深色 `#2e6b3a`；末尾 `/* ===== V2 P1-3 ===== */` 分节含 `data-theme` 的 `color-scheme` 钉住规则与 `.draft-tag` 样式。
- `app/src/store.test.ts` — 初始 state 断言补 `drafts` 字段（fixture 适配，1 行）。

## 2. 接口契约

- **REST/WS/表结构：无变更**（本任务只改客户端，无新增端点、帧类型、迁移）。
- 客户端本地契约：
  - `localStorage["chat_drafts:<userId>"]` = `{"<convId>": "<草稿文本>"}`，仅文本，不回填失败发送。
  - `localStorage["chat_theme"]` = `"system"|"light"|"dark"`。
  - `<html data-theme>`：`light`/`dark` 时设置，`system` 时不设。
  - CSS 变量 `--link`、`--code-bg`、`--code-fg` 已按任务单定义（供 P1-4 使用）。

## 4. 未覆盖项与已知限制

- 深色 CSS 实现用了 `light-dark()` + `color-scheme`，而不是任务单建议的「媒体查询 + `[data-theme]` 两块重复变量」——效果相同且深浅值只写一处，构建产物与截图实测正常。依赖 Chromium ≥123（Tauri WebView2 常青版、Playwright Chromium 均满足）；**已知限制**：不支持的旧内核上 `light-dark()` 会解析失败。
- 发送失败不回填草稿是刻意行为（outbox 路径未动）；`typing` 优先级只有单测与代码路径覆盖，浏览器端未构造真实对方输入事件。
- 编辑态本身是会话内内存态，刷新后只恢复草稿不恢复编辑态 — 与原设计一致。
