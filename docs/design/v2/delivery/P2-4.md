# P2-4 文件传输助手 + 消息转发 / 收藏 — 交付文档

## 1. 实现摘要

迁移（新增）：

- `server/migrations/0015_self_conversations.sql` — 纯数据回填：`INSERT ... SELECT` 为每个既有用户插入 `type='self'`/`owner_id=本人` 会话与 owner 成员行；靠 `uq_self_conversation` 部分唯一索引 + memberships PK 幂等。

服务端：

- `server/src/domain.rs` —
  - `ensure_self_conversation(executor, uid)`：单条 CTE 原子完成「插会话（ON CONFLICT）→ 取会话 id → 补 owner 成员（ON CONFLICT DO NOTHING）」，并发/重复安全，注册事务与兜底共用。
  - `PostMessage` 新增 `forwarded_from`（写入 `messages.forwarded_from`）与 `forward_attachment`（仅服务端转发路径可达的「已校验附件」入口；普通 `send_message` 恒为 `None`，`load_attachment` 的归属校验不受影响）。
  - `clone_attachment`：目标事务内 `INSERT ... SELECT` 克隆附件行——新 `id`、`conv_id`=目标、`uploader_id` 保持原上传者、九个元数据字段原样复制，共享 `storage_path`/`thumb_path` 物理文件。既有孤儿清理按 `storage_path` 计数，源删除不影响副本。
  - `forward_message`：源侧先成员校验（403）→ 墓碑 400「消息已删除」→ 投票 400「投票不能转发」；逐目标独立 `post_message`，`client_msg_id = fwd:<op>:<目标id>`，`forwarded_from` = 源发送者展示名快照，`reply_to_id` 置空；逐条映射 `Forwarded::Ok/Fail{code,message}`，目标失败不拖垮其他目标。
- `server/src/ws.rs` — 新消息广播 + 取消归档偏好推送提成 `pub async fn broadcast_posted(st, conversation_id, &Posted)`，WS `send_message`、REST `create_poll`、REST `forward` 三处共用；WS `send_message` 构造 `PostMessage` 时 `forwarded_from/forward_attachment` 恒 `None`；`send_typing` 对 `self` 会话显式短路。
- `server/src/api.rs` — 路由 `POST /v1/messages/{id}/forward`：`uid_of` 鉴权 → `rate_limit("fwd:<uid>")` → 目标数 1–10 校验 → 保序去重 → `domain::forward_message` → 每个成功目标 `broadcast_posted` → 逐条序列化 `{conversation_id, ok, message?, error?, message_text?}`；注册事务内 `ensure_self_conversation`（与用户/会话同事务，失败整体回滚）；self 守卫：踢人/改名/解散/转让显式 400（拉人/退出既有「非 group 400」分支覆盖，建投票由 domain「非 group 400」覆盖）。
- `server/src/model.rs` — `ForwardReq{conversation_ids, client_op_id:Uuid}`、`ForwardResp`、`ForwardResultItem`。

客户端：

- `app/src/types.ts` — `ForwardResultItem`（含 `message_text`）、`ForwardResp`。
- `app/src/api.ts` — `msgs.forward(id, conversation_ids, client_op_id)`。
- `app/src/store.ts` — `convTitle` 对 `kind==='self'` 返回「文件传输助手」。
- `app/src/ui/forwardTargets.ts`（新）— 转发目标纯函数：self 置顶、其余按列表顺序、排除已知只读私聊（好友未加载不过滤，交服务端逐条报错）。
- `app/src/ui/ForwardModal.tsx`（新）— 搜索 + 多选（≤10）、busy/错误态、`prepareForwardSubmission`：目标集合规范化后未变则复用同一 `client_op_id`（结果未确认的重试幂等）；成功目标立即并入本地缓存（广播帧按 id 去重），逐条失败原因内联展示。
- `app/src/ui/ChatView.tsx` — self 副标题「在你的设备间同步消息与文件」、无群信息按钮；消息 hover 操作条与右键菜单新增「转发 ➦」「收藏 ⭐」（非乐观、非墓碑、非投票消息；`canForwardMsg` 独立于只读态）；`doFavorite` = 转发到本人 self 会话，成功 toast「已收藏到文件传输助手」；气泡顶部 `.fwd-from`「转发自 {forwarded_from}」；self 会话不发 typing（服务端短路兜底）；挂载 `ForwardModal`。

## 2. 接口契约

- REST 新增：`POST /v1/messages/{id}/forward`，body `{conversation_ids: uuid[1..=10], client_op_id: uuid}`；恒 200 返回 `{results: ForwardResultItem[]}`（与去重后目标一一对应）。源侧统一拒绝：非成员 403、已删除/投票/目标数越界 400。目标侧逐条 `ok=false, error∈{forbidden,not_friends,bad_message,bad_request}, message_text=中文原因`。
- WS：无新帧类型；转发消息走既有 `message` 帧广播；幂等命中（`inserted=false`）不重复广播。
- 表结构：仅数据迁移（0015），无 DDL；`conversations`/`memberships`/`messages.forwarded_from`/`message_views` 均由 P2-0(0012) 建好，未再动视图。
- `PostMessage`/`Forwarded`/`broadcast_posted` 为内部 API，不暴露协议面。

## 4. 未覆盖项与已知限制

- `forwarded_from` 是转发时刻的展示名快照，源发送者改名/删除后旧转发标签不变（按任务单语义，刻意）。
- 附件转发共享物理文件：源消息/附件行的删除仅减引用，最后一个引用消失后孤儿物理文件由既有异步清理回收（测试轮询已验证）。
- 只读 DM 在客户端转发目标列表中：好友已加载时客户端预过滤，未加载时保留并由服务端逐条返回 `not_friends`（弹窗内联展示）。
- 浏览器实测覆盖任务单三条场景；投票消息转发 400、删除后转发 400、部分失败 UI 展示由集成测试与代码路径覆盖，未在浏览器端逐一构造。
- 多设备同步帧只对同一 uid 的连接广播，浏览器实测用「同账号两个浏览器上下文」等价验证。

## 5. 发现的其他问题

- **修了一处基线 bug**：`ChatView.onFile` 先取 `e.target.files`（Chromium 下是活 FileList）再清 `e.target.value=""`，清值会把已取出的列表同步清空，`fl?.length` 恒为 0 → 📎 文件选择器从未生效（粘贴路径不受影响）。本任务浏览器场景必须走文件选择器，已在 `ChatView.tsx` 内最小修复（先 `Array.from` 快照再清值），verify.mjs 文件上传场景依赖此修复。
- `cargo run`/`&` 起后端两条命令在本环境被非交互拒绝；改用后台 shell 直接跑 `target/debug/chat-server.exe` 完成实测，验证后已关闭（000 探测确认）。记为环境限制，不影响交付。
- `it.rs` 初版 `p24_forward_text_to_dm_and_group` 误加了一条多余的 `next_of`（`ws_send` 等 ack 时已消费自身 message 广播）导致挂起——纯测试自身帧序问题，已修，非产品代码问题。
