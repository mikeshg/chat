## 2. 接口契约

REST（与任务单一致，无偏差）：

- `GET /v1/server-info`（公开）→ `{ registration_mode: "open"|"invite"|"closed" }`
- `GET /v1/admin/settings` / `PUT /v1/admin/settings`（patch，未知值 400，返回完整设置）
- `GET /v1/admin/invites` → `created_at DESC`：`{ id, code, note, created_by_name, max_uses, uses, expires_at, revoked_at, created_at, usable }`，`usable` 服务端算
- `POST /v1/admin/invites` `{ max_uses? 1–1000, expires_in_hours? 1–8760, note? ≤100字 }` → 新建条目
- `DELETE /v1/admin/invites/{id}` → 幂等撤销，204
- `POST /v1/auth/register` 增可选 `invite_code`（trim + 大写规范化；open 忽略；invite 必填且原子消费；closed/错码 403）

表结构：同任务单 SQL（`server_settings`、`invites`、`users.invite_id`）。

无 WS 变更。兼容性：旧客户端不带 `invite_code` 在 open 下行为不变；`server-info` 失败按 open。

## 4. 未覆盖项与已知限制

- 浏览器实测用无头 Chromium + 同源托管（`app_dist`），未走 `vite` dev server 与真实窗口；二者对 UI 行为等价。
- Tauri 端「复制链接」路径在浏览器里不可达（origin 非 tauri.localhost 时走 `location.origin` 分支，已验证）；`getServer()` 为空时退化为只复制码的分支靠 `invite.test.ts` 单测覆盖。
- 剪贴板在测试环境可用，手动复制 `window.prompt` 回退未实机触发（代码路径存在）。
- 测试在 Postgres 上新建了 `chat_p12_browser`、`chat_p12_ui_*` 等一次性库（与 `chat_test`/`chat_t_*` 同一约定，未 drop）。
- `server_info`/`get_settings` 每请求一次 `SELECT`（任务要求不缓存），量级可忽略。
