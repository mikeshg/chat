- `app/src/ui/voice.test.ts` / `notify.test.ts` / `convPreview.test.ts` — 格式挑选、宽度、时长、过短、通知与列表预览。

## 2. 接口契约

与任务单一致。

- `POST /v1/files` multipart 增加可选 `duration_ms`。MIME 不以 `audio/` 开头、不是整数、或不在 1–300000 → 400。成功时 `AttachmentView.duration_ms` 为该值；不传则为 `null`。
- 发送带 `duration_ms` 的附件：`kind='audio'`，正文为空时 `content='[语音]'`。历史、WS `message`、`sync_messages` 都走同一 `message_views`，时长字段一致。
- 不带 `duration_ms` 的 `audio/mpeg` 仍是 `kind='file'`，正文占位 `[文件] <文件名>`。
- 编辑：`kind != 'text'` 已拒绝（语音实测 PATCH 400）。删除后视图把附件列掩成 NULL，`duration_ms` 不再出现。
- 无新 WS 帧类型，无表结构变更（`attachments.duration_ms` 已由 0012 建好）。

客户端差异：气泡最短宽度做成 140px 而不是任务单写的约 80px。80px 放不下「播放」按钮和进度条（浏览器截图可见）。120 秒仍封顶 220px，中间线性。

## 4. 未覆盖项与已知限制

- Windows WebView2：未做桌面自动化。wry 0.55.1 只在 `clipboard` 开启时把剪贴板权限设为 Allow，麦克风走 WebView2 默认 `PermissionRequested`。当前桌面应用从 `https`/`http` 源打开时，系统/WebView2 会弹「此站点想使用你的麦克风」；`NavigateToString` 场景则弹「This file wants to use your microphone」。本应用托管在 HTTP 源，预期弹权限框，用户允许后 `getUserMedia` 才能继续。未改 wry。
- Android：`gen/android` 里没有生成的 `WebChromeClient`。wry 0.55.1 `RustWebChromeClient.onPermissionRequest` 看到 `android.webkit.resource.AUDIO_CAPTURE` 时会 `permissionLauncher.launch` 申请 `RECORD_AUDIO` 和 `MODIFY_AUDIO_SETTINGS`，通过后 `request.grant`。Manifest 已声明这两项，因此网页麦克风请求会触发系统运行时权限。未改生成代码，也未改 wry。
- 浏览器实测走 Vite 开发页（同源代理到本槽位后端），不是 Tauri 壳。假设备无真实音轨，只断言元素进入播放态。
- 气泡最短 140px，见上。录音条在录音时替换输入框（`:has(.voice-bar)` 隐藏 textarea 和发送按钮），取消后恢复。
- 不做语音转文字、变速、长按说话、波形图。
