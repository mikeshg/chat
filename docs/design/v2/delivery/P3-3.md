## 2. 接口契约

- 表：`push_settings(user_id uuid PK→users ON DELETE CASCADE, enabled bool=false, topic text UNIQUE, preview bool=false, updated_at)`。
- `server_settings` 键：`push_ntfy_base`（http/https ≤200，空=关）、`push_ntfy_token`（只写，GET 只回 `push_ntfy_token_set`）、`public_url`（同校验，空=不带 Click）。
- REST：
  - `GET /v1/users/me/push` → `{available, enabled, preview, subscribe_url}`；`subscribe_url={push_ntfy_base}/{topic}`，未配置为 `null`；首次访问生成主题建行。
  - `PUT /v1/users/me/push`，body `{enabled?, preview?}` → 同上；未配置时 `enabled=true` → 400「管理员未配置推送服务」。
  - `POST /v1/users/me/push/rotate` → 同上（新主题，旧主题作废）。
  - `POST /v1/users/me/push/test` → 200 同上视图；投递失败 502 带原因。
  - `GET /v1/server-info` 增 `push_available: bool`。
- WS 入站：`{type:"client_state", active:bool}`；出站无新帧。心跳：服务端仍按周期发 Ping；任何入站帧刷新 `last_inbound`；静默超过 `ws_idle_timeout_ms`（默认 75s）即关闭连接并走正常离线广播。
- 推送：ntfy JSON 发布接口 `POST {push_ntfy_base}`，body `{topic,title,message,priority(1-5),tags,click}`，`Authorization: Bearer` 当有令牌。
- 与任务单差异：发送走任务单建议的 JSON 接口（`POST {base}` + JSON body），不是 `POST {base}/{topic}` + 头部方案——任务单原文明示「建议直接用 JSON 接口，避免头部编码问题」，两者选一故不算偏离；priority 用 ntfy 整数刻度 3/4 对应 default/high。

## 4. 未覆盖项与已知限制

- 合并窗口 `push_last` 是单实例内存状态（`// ponytail:`）：重启丢失，重启后 30s 内可能多推一条，任务单认可。
- 心跳超时在 ping tick 上检查：实际关闭时刻 ∈ (timeout, timeout+ping_interval]，非精确时刻；旧客户端不发 `client_state` 按 active=true 处理（保守不误推，但也意味着旧客户端驻留后台时不会触发推送——兼容语义如此）。
- 新客户端连旧服务端：`client_state` 帧会得到 `bad_frame` 错误帧，客户端仅 `console.warn`，功能无损。
- 推送无重试队列、无送达统计（任务单明确不做）；ntfy 5s 超时/失败仅记日志。
- 假 ntfy 走 JSON 发布接口已验证 topic/title/message/priority/tags/authorization/click；真实 ntfy.sh 服务器未实测。

## 5. 发现的其他问题（范围外，只记录）

- `app/src/ws.ts` 模块级 `window`/`document` 事件监听在 Vitest（node 环境）下不注册，`reportClientState` 的 DOM 事件链路只能靠浏览器实测间接覆盖（本次实测中 bob 关闭页面即由 WS 断开覆盖，未单独验证 `visibilitychange` 上报链路的真实 DOM 触发）。
- `AdminSettings.tsx` 的 `saved` 提示与「注册设置」共用同一个 `ad-saved` 徽标位置——推送保存成功时徽标显示在注册设置行旁边而非推送栏，属既有样式约定，未改。
