## 2. 接口契约

- `PUT /v1/users/me/avatar`：multipart 字段 `file`。成功返回 `UserPublic`（`avatar_version` 从 0 起 +1，`has_avatar=true`）。格式不对或 > 1MB 返回 400。路由 body 上限 1MB + 1MB 表单余量，不使用附件的 25MB。
- `DELETE /v1/users/me/avatar`：返回更新后的 `UserPublic`。有头像时 `avatar_path = NULL` 且 `avatar_version + 1`；已经没有头像时不再递增（任务单只要求删除头像时递增，避免空点刷新失效所有缓存）。
- `GET /v1/users/{id}/avatar?v=`：无需鉴权。有头像返回图片字节和 `X-Content-Type-Options: nosniff`。`v` 等于当前版本时 `Cache-Control: public, max-age=31536000, immutable`，否则 `no-cache`。无头像 404。
- WS：头像变更后向 watchers 和本人其他连接发已有的 `invalidate { what: "conversations" }`。未新增帧类型。
- 存储名：`avatars/<user_id>-<version>.png|jpg|webp`。未改 `message_views`，未加迁移。
- 与任务单的差异：`AdminUserView` 额外带 `avatar_version` / `has_avatar`（可选），否则管理列表没有数据可渲染头像。

## 4. 未覆盖项与已知限制

- 不解码图片，只认文件头魔数。损坏但魔数正确的文件会被存下，浏览器加载失败后回落首字母。
- 没有交互式裁剪框；客户端固定居中裁成正方形再缩到 256。
- 群会话图标仍是首字母，不做群头像。
- 没有头像审核。
- 并发更换用 `avatar_version` 条件更新，冲突时 409，客户端显示错误后可重试。
- 浏览器实测用 Web PNG 上传路径；WebP 导出依赖浏览器 `canvas.toBlob`，单测只覆盖裁剪矩形。
