## 2. 审查要点

- **P4-1 的实测发现并修复了一个真 bug**：恢复原本跑在 HTTP 请求的 future 上。管理员被踢下线后，页面跳转会中断这次请求，axum 随之丢弃 handler，数据库回滚了，但维护模式标记永远不会复位，服务永久 503。现在恢复在 `tokio::spawn` 的独立任务里执行，维护标记、忙碌锁、上传临时文件都由 Drop 守卫兜底。
- **循环外键**：库里存在真实的循环外键（`users.invite_id` → `invites`，`invites.created_by` → `users`），单纯按外键顺序 COPY 排不出来。实现是在恢复事务里临时卸下循环 / 自引用的外键，灌完数据后用 `pg_get_constraintdef` 原样装回（装回时 Postgres 整表校验）；任何一步失败，整个事务连同约束变更一起回滚。
- **凭证作废**在事务提交后、退出维护模式前完成，这段时间外部请求都被 503 挡住。
- **已知限制**：备份期间新上传的文件可能不在快照里（代码里有 ponytail 注释）。文件替换原本中途失败会留下部分状态，审查后已改为可撤回，见 [review-gpt6-astar.md](review-gpt6-astar.md) 第 1 条。
- **P4-2**：README 漏了 5 项 V2 功能（系统通知、草稿、链接与代码块、暗色模式、存储配额），审查时补上；合并后再补上备份与恢复一项。
