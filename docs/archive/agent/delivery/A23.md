# A23 交付

宿主掉线不再立刻终止进行中的调用。结果和审批决定在重连后补发。取消可以先于 `invocation_start` 到达，宿主不会把这次调用跑起来。

## 1. 实现摘要

- `server/migrations/0032_host_offline_grace.sql`：`agent_hosts.offline_since`，宽限起点。
- `server/tests/migrations.rs`：迁移列表末尾加上 `0032`。
- `server/src/state.rs`：`host_offline_grace_ms`（默认 10 分钟）、`inv_gate`（全局锁，只包一次状态查询和一次非阻塞发送；吞吐成问题时按调用 id 分锁）。
- `server/src/host_ws.rs`：断开只记 `offline_since` 并推离线；`host_hello` 读可选的 `running` / `pending_approvals`；`host_ready` 入队后核对并补发，再清排队。
- `server/src/agents.rs`：重连核对（保持 / 重建运行时条目 / `failed/host_disconnected` / 补发取消）；宽限清扫并入排队清扫循环，只失败当前不在线的宿主，在线宿主残留的 `offline_since` 清成空；取消成功后一律通知宿主并摘掉 `inv_runs`；下发 start 前在锁内再看状态。
- `server/src/approvals.rs`：按宿主报告的 `request_id` 补发已决定的 `approval_decision`。
- `server/tests/it.rs`：A23 七则集成测试（含在线宿主不被宽限清扫误杀）；原先「一断线就失败」的三则改为宽限内保持原状态。
- `scripts/e2e.mjs`：关掉宿主连接后调用仍是 `running`；同一 `install_id` 重连且 hello 不带 `running` 时变为 `failed/host_disconnected`。
- `CONTEXT.md`：宿主离线一条补上进行中调用的说法（本机继续跑，重连补发结果，10 分钟没回来判失败）。
- `agent-host/src/outbound.rs`：跨连接出站队列，以及先到取消的有界记录。
- `agent-host/src/conn.rs`：调用任务不绑在某一条连接上；`host_hello` 带上还在跑的调用和等待中的审批；断线不清审批。
- `agent-host/src/lib.rs`：挂上出站队列；`shutdown` 先取消重连循环再摘掉写任务，套接字会关。
- `agent-host/src/runtime.rs`：审批登记表可以列出还在等的 `request_id`；普通断线不再清空。
- `agent-host/tests/reconnect.rs`：假 WS 服务端加 `fake-acp-agent.mjs` 的三则测试。

## 2. 接口契约

- `host_hello` 增加可选字段，旧宿主不带时按空数组处理：
  - `running`：`string[]`，还在进行的调用 id（含 finish 已生成但套接字还没写成功的）。
  - `pending_approvals`：`string[]`，还在等决定的审批 `request_id`。
- 重连后、`host_ready` 之后，服务端可能再发已有帧：`invocation_cancel`、`approval_decision`。没有新的帧类型。
- 表：`agent_hosts.offline_since timestamptz NULL`。断开时若为空则写成 `now()`，重连清成 `NULL`。没有 REST 字段变化。
- `AppState.host_offline_grace_ms` 默认 `600_000`。到期且宿主当前不在线：进行中的调用 `failed` / `host_disconnected`，未决审批过期，推送与原先的失败帧相同。在线宿主即使 `offline_since` 还在，清扫只把该列清成空，不改调用状态。服务端重启后内存里没有连接时，清扫对「有进行中调用但 `offline_since` 为空」的宿主把起点写成 `now()`，再按这一列判断。
- 与任务单一致。没有新的依赖。

## 4. 未覆盖项与已知限制

- 离线期间的 `invocation_event` 不补发。finish 里有全文和步骤。
- 产出文件的 HTTP 上传失败不重试。
- 撤销设备与宿主握手复核不在本票（A24）。
- 套接字已经写成功、确认还没记上就断线时，重连可能再送一次 finish。调用若已是终态，服务端忽略，不会再写一条回复。
- 宽限的进程重启路径靠清扫读 `offline_since`（测试里清掉 `inv_runs` 并把该列拨到过去）。没有另起一次操作系统进程做崩溃演练。
- 同一 `install_id` 被另一进程顶替时，新进程的 hello 不带旧调用，服务端按「没报告」判 `host_disconnected`。旧进程不再重连。
