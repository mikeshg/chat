## 2. 接口契约

### 表结构（0026）

```sql
ALTER TABLE agent_invocations ADD COLUMN attachment_ids uuid[] NOT NULL DEFAULT '{}';
ALTER TABLE attachments ADD COLUMN agent_invocation_id uuid
    REFERENCES agent_invocations(id) ON DELETE SET NULL;
CREATE INDEX idx_attachments_agent_invocation ON attachments(agent_invocation_id)
    WHERE agent_invocation_id IS NOT NULL;
```

### REST

`POST /v1/agent-tools/files`（multipart `file`，`Authorization: Invocation <tools_token>`）→ `{attachment_id}`；413 `{code:"quota_exceeded"}`；调用结束 / 普通 bearer / 伪造一律 401。

### WS 帧

- `invocation_start` 加 `attachments: [{id,name,mime,size}]`（可缺席 = 空）。
- `invocation_finish` 加 `files: [attachment_id]`、`files_skipped: <n>`。
- `InvocationView`（REST 列表 + `invocation_*` 帧）加 `attachment_ids`，旧客户端忽略。

### 宿主本地约定

`<data_dir>/inv-<id>/in|out`，env `CHAT_AGENT_OUTBOX`，调用结束整目录删除。

### 与任务单不一致处（自选项均已说明）

- **加迁移**：任务单二节允许「存一列」时用 0026。选持久化而非按规则现算：attachment_ids 同时要出现在 InvocationView（前端提示）、invocation_start（宿主）、排队调用提升三处，入库即定最简单且可审计；「待交付」改由 NOT EXISTS 反查定义，天然避开「上限留下的附件永远滞留但仍显示提示」的不一致（超上限的附件会被后续调用补带走，提示语义自洽）。
- 收集窗口实现为「触发消息 seq 之前、未被任何调用带走」，与任务单「上次触发之后、本次触发之前」在正常时序等价，且并发触发下无窗口缝隙。

## 4. 未覆盖项与已知限制

- 群 / 私聊附件、语音消息、Agent 经消息工具发附件（A16）：任务单明确不做。
- 附件消息在待交付期间被删除：收集时 `deleted_at IS NULL` 过滤，删除即不再带走；已带走后删除附件行，宿主按缺席处理（meta 里就没有该项）。
- `collect_outbox` 只取普通文件、文件名排序前 10，更多文件记日志丢弃（`files_skipped` 只统计上传 413，不统计超上限丢弃——丢弃在子进程侧不可见，且任务单只要求配额计入 skipped）。
- resume/load 路径带附件（重新下载同一批），未对已落盘文件做续传复用。
- 浏览器实测只覆盖了「提示 + inspect + makefile」正向路径；`--no-image` / 配额 / 跨调用归属由 Rust 集成测试覆盖。
