# A15 交付：子调用在原会话里嵌套显示

对应 Gitea issue `xiefan/chat#16`。没有新迁移。

## 1. 实现摘要

- `server/src/model.rs`：`InvocationView` 增加可选字段 `result_preview`（不落库，`#[sqlx(default)]`，查询没带这一列时为 null）。
- `server/src/agents.rs`：`GET /v1/conversations/{id}/agent-invocations` 在原有 `conversation_id = 该会话` 之外，同时返回 `root_conversation_id = 该会话` 的子调用。成员校验不变。子调用进入 `succeeded` 时，成功帧带回复正文前 2000 个 Unicode 标量；历史列表用 `left(result_text, 2000)` 现算。其余调用和非终态为 null。不把 `result_text` 放进帧。
- `server/tests/it.rs`：末尾 `// ===== Agent A15 =====` 增加 `a15_group_child_preview`。`a14_offline_callee_queues` 改为按 Agent 名找父调用：列表现在会把更晚创建的子调用排在前面，`[0]` 不再一定是父调用。
- `app/src/invocationTree.ts`：纯函数。帧 / 历史按调用 id 覆盖进「父调用 id → 子调用」，再按 `created_at` 排成派出顺序；从父调用展开最多 5 层，更深标 `deeper`。
- `app/src/store.ts`：`childInvocations` 由 `applyInvocations` 维护（`agent_invocation` 帧和历史 GET 走同一入口）。子调用的流式输出仍在 `agentRuns[子调用.conversation_id][invocation_id]`。
- `app/src/ui/NestedInvocation.tsx`：父调用状态行下面的嵌套卡片。默认收起。标题 `↳ 🤖 <agent_name> · <状态>`，状态文案复用 `InvocationStatusLine`（含已用时长和当前步骤）。展开后：进行中且已有流式输出时用 `LiveRunBubble`；成功显示 `result_preview`，满 2000 字加「…」；失败 / 取消 / 超时显示原因。子调用的子调用缩进一级，第 5 层之下显示「还有更深的调用」。卡片上没有取消按钮。
- `app/src/ui/AgentRun.tsx`：`InvocationStatusLine` 增加 `textOnly`，嵌套标题不要图标和消息行左缩进。
- `app/src/ui/ChatView.tsx`：每个调用状态行下挂一行 `<NestedInvocations parentId={inv.id} />`。
- `app/src/types.ts`：`InvocationView.result_preview?`。
- `app/src/styles.css`：末尾 `/* ===== Agent A15 ===== */`，颜色用已有 CSS 变量。
- 测试：`invocationTree.test.ts`、`NestedInvocation.test.tsx`，`store.test.ts` 补子调用索引。

## 2. 接口契约

无新表、无新迁移、无新路由。

### REST

`GET /v1/conversations/{id}/agent-invocations?limit=`

- 成员校验不变：非成员 403 `not a member of this conversation`。
- 返回该会话自己的调用，以及 `root_conversation_id` 等于该会话的子调用。同一行只出现一次。
- 仍按 `created_at DESC, id DESC`，`limit` 默认 50、最大 200，作用在合并后的结果上。子调用通常更晚创建，会排在父调用前面。
- `InvocationView` 增加 `result_preview`：
  - 有 `parent_invocation_id` 且 `status = succeeded`：`result_text` 的前 2000 个字（PostgreSQL `left` / Rust `chars().take(2000)`，按 Unicode 标量，不按字节）。
  - 其余情况：`null`。
- 响应里没有 `result_text`。

### WS

`agent_invocation` 帧的 `invocation` 同样带 `result_preview`。只有子调用成功的那一帧是正文摘要；进行中、失败、取消，以及没有父调用的成功帧都是 `null`。

与任务单的差别：成功但正文为空时，帧和历史里是 `""` 而不是 `null`（`left('', 2000)` 与 `chars().take` 都得到空串）。非子调用和非成功态仍是 `null`。

## 4. 未覆盖项与已知限制

- `limit` 作用在「本会话调用 ∪ 根在本会话的子调用」这一份倒序列表上。本会话自己的调用很多时，更老的子调用可能被挤出这一页，刷新后嵌套会缺。
- 客户端把长度达到 2000 个码位的预览一律显示「…」。正文刚好 2000 字时也会带省略号。
- 成功态的查表组件本来不渲染（父调用靠定稿消息表达结束）。嵌套卡片标题在成功时另写「完成」，否则展开前看不出已经结束。
- 第 5 层卡片只要下面还有调用，就显示「还有更深的调用」，不再画出第 6 层。
- `root_conversation_id` 没有索引。任务单不允许加迁移。
- 没有启动 Tauri 窗口。桌面壳只做了 `cargo check`。

## 5. 发现的其他问题（范围外）

- 群成员看到的父调用「生成中」气泡名称是「Agent」，不是 `a`。`ChatView` 只在「本会话是 Agent 专属会话」或「调用者自己的 Agent 列表」里找名字；群成员的列表里没有别人的 Agent。子卡片用的是帧里的 `agent_name`，所以子调用名字是对的。这次没改父气泡。
