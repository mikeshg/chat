# A01 交付：最小端到端——在专属会话里调用 Agent 并收到回复

对应 Gitea issue `xiefan/chat#2`。迁移号 `0019_agents.sql`。

## 1. 实现摘要

### 数据层

- `server/migrations/0019_agents.sql`：新建 `agent_hosts`、`agents`、`agent_invocations` 三表；`conversations.type` 放开 `'agent'` 并加 `conversations.agent_id`（部分唯一索引保证每个 Agent 恰好一个专属会话）；`messages.agent_id NULL → agents`；重建 `message_views`（在原列后追加 `agent_id`、`agent_name`，列序其余照旧）。
- `server/tests/migrations.rs`：迁移列表追加 `0019_agents`。

### 服务端

- `server/src/model.rs`：`ConversationView.agent`（`{id,name,host_online}`）、`MessageView.agent`（`{id,name}`）、`AgentHostView` / `AgentView` / `AgentInvocationView`、WS 帧 `host_hello` / `host_ready` / `invocation_start` / `invocation_finish` / `agent_host_status` / `agent_invocation` 的类型。
- `server/src/state.rs`：宿主连接表 `hosts: HashMap<Uuid, HostConn>`（独立于普通连接表，不参与在线/推送判定）+ 增删查与「同 host_id 顶号」。
- `server/src/host_ws.rs`：`role=host` 会话——收 `host_hello`（10s 超时，首帧不对即断）→ upsert `agent_hosts` → 回 `host_ready` → 循环收 `invocation_finish`（只认本宿主发出的 finish）；断开时把该宿主全部 `running` 调用置 `failed`/`host_disconnected`；上下线推 `agent_host_status` 给主人普通连接并更新 `last_seen_at`。
- `server/src/agents.rs`：REST `GET /v1/agent-hosts`、`GET /v1/agents`、`POST /v1/agents`（事务内建 Agent + AgentConversation + 主人成员，成功后给主人推 `Invalidate{conversations}`）、`GET /v1/conversations/{id}/agent-invocations`（仅成员）；`dispatch_invocation`（宿主在线→`running`+`invocation_start`，离线→`failed`/`host_offline`）、`finish_invocation`（成功→以 `agent_id` 写消息、>4000 字符按序拆分；失败→记 `error` 截 500 字符）。
- `server/src/ws.rs`：`?role=host` 分流到 `host_ws`；`send_message` 落库后若为 agent 会话则触发 `dispatch_invocation`；agent 会话跳过 typing 广播与 `read_sync` 处理。
- `server/src/api.rs`：挂 4 条新路由；`list_conversations` 的 SQL/view 带 `agent` 字段；`add_members` / `remove_member` / `leave` / `rename` / `transfer` / `dissolve` / `create_poll` 的 `self` 守卫扩为 `self|agent`（返回 400）；`notify`（WS 路由里的 RestNotify）对 agent 会话不发 typing。
- `server/src/domain.rs`：`PostMessage.agent_id`；`MsgViewRow` + view SQL 带 `agent_id`/`agent_name`；`write_message` 对 agent 消息跳过 `last_read_seq` 推进（主人未读 +1）；`broadcast_posted` 对 agent 消息跳过给发送者的 `ReadSync`；`lock_message_for_mutation` 拒编 agent 消息。
- `server/src/push.rs`：agent 消息按「别人发来的」走离线推送（sender 显示 Agent 名）。
- `server/src/lib.rs`：`mod agents; mod host_ws;`。
- `server/Cargo.toml`：`[dev-dependencies] agent-host = { path = "../agent-host" }`。
- `server/tests/it.rs`：新增 `// ===== Agent A01 =====` 一节，10 个测试覆盖任务单 1–11（REST 越权/校验、会话限制、宿主生命周期、install_id 复用、echo 主路径、fail/crash、host_offline、host_disconnected、长文拆分、并发、调用历史）。

### 宿主运行时（新 crate `agent-host/`）

- `agent-host/Cargo.toml`：tokio / tokio-tungstenite(rustls-webpki) / futures-util / serde / serde_json / uuid / tracing；dev-dep reqwest（示例用）。
- `src/lib.rs`：`HostConfig`、`TicketSource` trait（异步取一次性 ticket）、`spawn() -> HostHandle`（`host_id()` / `wait_host_id()` / `shutdown()`，shutdown 会 abort 连接循环与所有在跑子进程）。

- `examples/host.rs`：命令行宿主 `cargo run --example host -- --server … --user … --password … [--install-id …] [--label …]`，REST 登录 + 401 刷新取票，install_id 落 cwd 文件。

## 2. 接口契约

### 表结构（`0019_agents.sql`）

- `agent_hosts(id uuid PK, user_id→users CASCADE, install_id uuid, label ≤60, platform, created_at, last_seen_at)` + `UNIQUE(user_id, install_id)`
- `agents(id, owner_id→users CASCADE, host_id→agent_hosts CASCADE, name, runtime jsonb, cwd, created_at, updated_at)` + `UNIQUE(owner_id, lower(name))`；name CHECK：`^[A-Za-z0-9_][A-Za-z0-9_-]{0,31}$`（1–32、字母数字`_-`、首字符非 `-`）
- `conversations`：type CHECK 加 `'agent'`；`agent_id→agents CASCADE`；`type='agent'` 上部分唯一索引
- `messages.agent_id uuid NULL→agents`；`message_views` 重建（末尾追加 `agent_id`、`agent_name`）
- `agent_invocations(id, agent_id→CASCADE, conversation_id, trigger_message_id, status CHECK(queued/running/awaiting_approval/succeeded/failed/cancelled/timed_out), error, created_at, started_at, finished_at)`

### REST

- `GET /v1/agent-hosts` → `[{id,label,platform,online,last_seen_at}]`（本人）
- `GET /v1/agents` → `[{id,name,host_id,host_online,runtime,cwd,conversation_id,created_at}]`（本人）
- `POST /v1/agents {name,host_id,runtime:{command,args},cwd}` → AgentView；校验：宿主非本人 404、`bad_name` 400、`name_taken` 409、command 非空≤500、args≤50
- `GET /v1/conversations/{id}/agent-invocations?limit=50` → `[{id,agent_id,conversation_id,trigger_message_id,status,error,created_at,...}]`，仅成员

### WS 帧

- 连接：`/v1/ws?ticket=…&role=host`；宿主→服务端 `{type:"host_hello",install_id,label,platform}`；服务端→宿主 `{type:"host_ready",host_id}`
- 服务端→宿主 `{type:"invocation_start",invocation_id,agent:{id,name,runtime,cwd},prompt}`；宿主→服务端 `{type:"invocation_finish",invocation_id,ok,text|error}`
- 服务端→主人普通连接 `{type:"agent_host_status",host_id,online}`、`{type:"agent_invocation",invocation:{…}}`
- 与任务单无契约偏差。

### 宿主库最终签名

`spawn(cfg: HostConfig, tickets: Arc<dyn TicketSource>) -> HostHandle`；`HostHandle::{host_id(), wait_host_id().await, shutdown().await}`；`TicketSource::ticket() -> Pin<Box<dyn Future<Output=Result<String,String>> + Send>>`。

## 4. 未覆盖项与已知限制

- 排队/超时/取消、流式输出、上下文延续、权限审批、跨会话 @、附件、Agent 编辑/删除、登记表、托盘：均属后续票（A02–A13），本票未做。
- Tauri 桌面实机验证未做（任务单声明归主会话验收）；桌面桥代码通过 `cargo check` + 类型检查，票据回路为编译期验证。
- 宿主 `data_dir`（agent cwd 为空时的兜底目录）暂用 `temp_dir()/chat-agent-host`，A09 做持久目录策略时可收敛。
- `POST /v1/agents` 的事务里 host 归属校验先于名字校验（顺序影响 400/404 呈现，均符合任务单语义）。

## 5. 发现的其他问题（范围外）

- `app/src-tauri/gen/schemas/*.json` 被 tauri-build 触碰但内容无实质 diff（line-ending/重写），随构建自然更新。
- 宿主连接不占普通在线位，故主人的好友不会看到「因宿主上线而在线」——符合预期，但手机端/网页端只看 `online` 好友列表时无法区分「人不在、宿主在」，后续票若要暴露「宿主在跑」需另设状态位。
