## 2. 接口契约

### 表

`agent_invocations` 新增：

| 列 | 说明 |
|---|---|
| `parent_invocation_id` | `uuid NULL → agent_invocations ON DELETE SET NULL` |
| `depth` | `integer NOT NULL DEFAULT 0` |
| `root_conversation_id` | `uuid NULL`，无外键。子调用继承父调用的根会话；父调用没有则用父调用的会话 |
| `result_text` | `text NULL`。成功时写入回复正文，按 Unicode 标量截到 10 万字符 |
| `context_key` | `text NULL`。任务单没有这一列。子调用存 `call:<上下文号>`，成功收尾和离线补发都用它找回运行时会话 |
| `prompt` | `text NULL`。任务单没有这一列。子调用的完整指令。触发消息只保留前 200 字的记录，离线补发不能拿它当指令 |

`agent_user_settings.max_call_depth integer NOT NULL DEFAULT 3 CHECK (1–10)`。

`agent_invocations_origin` 改为：`trigger_message_id`、`schedule_id`、`parent_invocation_id` 至少一个。删除时间表或删除父调用把唯一来源置空时放行。函数在 `0029` 里 `CREATE OR REPLACE`，没有改 `0027`。

### 调用凭据

`invocation_start.tools_token` 的 `depth` 等于该调用行的 `depth`。主人直接发起仍是 0。

### REST

`POST /v1/agent-tools/invocations`，`Authorization: Invocation <token>`，body `{ agent_name, prompt, context_id? }`。

- 在主人未删除的 Agent 里按名字找（不区分大小写）。没有 → `404 {"error":"agent not found"}`。允许调用这条链上正在跑的同一个 Agent，靠深度上限停住。
- `depth = 父 depth + 1`，大于 `max_call_depth` → `400 {"error":"depth_exceeded"}`。
- `context_id` 缺省则新生成 uuid；非法 → `400 bad_context_id`。上下文键 = `call:<context_id>`，按被调 Agent 区分。
- 在被调方专属会话里以被调方身份发「📨 被 @<调用方名字> 调用：<prompt 前 200 字>」，作为 `trigger_message_id`。
- 子调用的会话是被调方专属会话，`parent_invocation_id` 是当前调用，`root_conversation_id` 按上面的规则填。然后走 `deliver_invocation`（离线排队、权限档、审批都沿用）。
- `prompt` 空或超过 4000 字 → `400 bad_prompt`（任务单没写上限，与普通消息一致）。
- `200 {"invocation_id","context_id","status"}`。

`GET /v1/agent-tools/invocations/{id}?wait=<秒>`。

- 只有 `parent_invocation_id` 等于当前调用的行能看，否则 `404 {"error":"invocation not found"}`。
- `wait` 缺省 0，范围 0–600，超出 `400 bad_wait`。服务端每 200ms 看一次库，到终态或到点就返回。
- `{"invocation_id","status","result_text?","error?"}`。没有的字段省略。

`GET/PUT /v1/users/me/agent-settings` 增加 `max_call_depth`。缺省不改。非法值 `400 bad_max_call_depth`。没有设置行时读出来是 3。

### WS

`agent_invocation` 的 `InvocationView` 增加 `parent_invocation_id`、`root_conversation_id`、`agent_name`。没有父调用 / 根会话时这两个 id 是 `null`。

子调用的状态帧除了被调方会话成员，也推给根会话成员。登记运行时状态时把根会话成员并进 `member_ids`，所以 `agent_stream` 同样送到根会话。

取消级联：主人取消、使用权收回、删除 Agent 之后，未结束的后代改为 `cancelled`，向各自宿主发 `invocation_cancel`（仅原来是 `running` / `awaiting_approval` 的），并推状态帧。主人取消时后代的 `error` 为空；收回使用权时后代的 `error` 是 `agent_access_revoked`。

### 宿主工具

- `call_agent`：`name`、`prompt`、`wait`（默认 true）、`context_id`（可选）。`wait=false` 立刻返回调用号和上下文号。`wait=true` 最多等 600 秒；超时文本以「仍在运行」开头，带调用号，并提示用 `wait_invocation`。
- `get_invocation`：`invocation_id`，立刻返回状态，有结果时带正文。
- `wait_invocation`：`invocation_id`、`timeout_secs`（默认 300，超过 600 按 600）。

描述写明只能调用主人的其他 Agent；并行时 `wait=false` 再逐个 `wait_invocation`。

假 agent：

- `call:<名字>:<指令>` → 同步调用，回复是结果正文。
- `callasync:<名1>,<名2>:<指令>` → 并行派出后逐个等待，用 `|` 连接。
- `callctx:<名字>:<上下文号|new>:<指令>` → `ctx=<上下文号> result=<正文>`。

## 4. 未覆盖项与已知限制

- 原会话里的嵌套卡片是 A15。本票只让帧里带上父调用、根会话和名字。
- 宿主断开把该宿主上 `running` / `awaiting_approval` 标成失败，不级联取消其他宿主上的子调用。任务单点名的取消路径是主人取消、使用权收回、删除 Agent。
- `result_text` 存的是写进会话的回复正文（定时调用会带上「⏰ 定时任务」那一行），不是宿主原始分片。
- `GET ?wait=` 在父调用结束时重新验凭据，父调用已取消则中途 401，不再一直占着连接。
- 没有启动 Tauri 窗口。桌面壳只做了 `cargo check`。
- 没有新的 CSS。深度选择沿用现有的设置行样式。
