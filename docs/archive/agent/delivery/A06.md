## 2. 接口契约

### 表（`0023_agent_config.sql`）

`agents` 新增：

| 列 | 定义 |
|---|---|
| `extra_dirs` | `text[] NOT NULL DEFAULT '{}'` |
| `model` / `mode` | `text NOT NULL DEFAULT ''`（空串 = agent 默认） |
| `instructions` | `text NOT NULL DEFAULT ''`，`char_length <= 8000` |
| `env` | `jsonb NOT NULL DEFAULT '{}'` |
| `avatar_version` | `integer NOT NULL DEFAULT 0` |
| `avatar_path` | `text NULL`（见下） |
| `reported_options` | `jsonb NOT NULL DEFAULT '{}'` |
| `deleted_at` | `timestamptz NULL` |

`uq_agents_owner_name` 改为 `UNIQUE (owner_id, lower(name)) WHERE deleted_at IS NULL`。

`message_views` 末尾追加 `agent_avatar_version`。

与任务单的差异：多了 `avatar_path`。用户头像靠路径记住扩展名（png / jpg / webp），只存 `avatar_version` 无法取回文件。该列不出现在 JSON 里。

`model` / `mode` 服务端另限 200 字符（`bad_model` / `bad_mode`），任务单未写长度，避免无界文本。

### REST

- `PATCH /v1/agents/{id}`：可改 `name`、`runtime`、`cwd`、`extra_dirs`、`model`、`mode`、`instructions`、`env`，以及原有 `output_mode`、`queue_timeout_secs`。缺省不改；覆盖项显式 `null` 清除。带 `host_id`（任何值）→ 400 `host_immutable`。已删除、不存在、别人的 → 404。重名 → 409 `name_taken`。非法值 400：`bad_name`、`bad_runtime`、`bad_extra_dirs`、`bad_instructions`、`bad_env`、`bad_model`、`bad_mode`、`bad_output_mode`、`bad_queue_timeout`。
- `GET /v1/agents` 与 `PATCH` 响应的 `AgentView` 增加 `extra_dirs`、`model`、`mode`、`instructions`、`env`、`reported_options`、`avatar_version`、`deleted`。这两个接口本来就只返回本人的 Agent，环境变量因此只在主人自己的响应里。会话列表和消息视图不带 `env`。
- `DELETE /v1/agents/{id}` → 204。软删除。`GET /agents` 不再列出。进行中调用变为 `failed` / `error=agent_deleted`，并向宿主发已有的 `invocation_cancel`。
- 之后在该专属会话发消息：WebSocket 错误帧 `code=agent_deleted`（领域错误码走 `post_err` 时对应 HTTP 400；发送入口是 WS，没有 REST 发消息）。不落库、不产生调用。`ConversationView.agent.deleted=true`，会话仍在列表里。
- `PUT /v1/agents/{id}/avatar`：multipart 字段 `file`，PNG / JPEG / WebP，上限与用户头像相同（1MB）。成功 `avatar_version + 1`，返回 `AgentView`。别人或已删除 → 404。
- `GET /v1/agents/{id}/avatar?v=`：无需登录。`v` 等于当前版本时 `Cache-Control: public, max-age=31536000, immutable`，否则 `no-cache`，并带 `X-Content-Type-Options: nosniff`。已删除的 Agent 头像仍可取，历史消息还能显示。
- `POST /v1/agents/{id}/probe`：宿主在线 → 202 `{"ok":true}`，并下发 `{"type":"agent_probe","agent":{…快照…}}`。离线 → 409 `host_offline`。

### WS

- `invocation_start.agent` 与 `agent_probe.agent` 快照：`id`、`name`、`runtime`、`cwd`、`extra_dirs`、`model`、`mode`、`instructions`、`env`。配置在下一次调用生效。
- 宿主 → 服务端 `{"type":"agent_options","agent_id","modes":[{"id","name"}],"models":[{"id","name"}]}`。服务端写入 `reported_options`（形状 `{"modes":[…],"models":[…]}`），给主人推 `invalidate` / `what=agents`。ACP 的模型 id 字段 `modelId` 在上报前收成 `id`。
- `MessageView.agent` 增加 `avatar_version`。`ConversationView.agent` 增加 `avatar_version`、`deleted`。

### 宿主

`RunRequest` 增加 `env`、`instructions`、`model`、`mode`、`extra_dirs`、`probe`。`AgentSpec::from_json` 解析同名字段，缺省为空。`probe=true` 时只做 `initialize` + `session/new` 后结束子进程。

## 4. 未覆盖项与已知限制

- 没有在浏览器里上传头像并核对三处图片；上传、版本号、缓存头和越权 404 由 `a06_avatar_upload_and_acl` 覆盖，界面组件已接上。
- `model` / `mode` 超过 200 字符会 400，任务单没有写这个上限。
- 附加指令只写在「新建会话」分支。当前宿主每次调用都是新会话；A02 的恢复路径还没合进来，合入时不要把这段复制到恢复分支。
- 假 agent 的 `whoami` 看的是 prompt 最后一个文本块。附加指令在第一块，所以不会把指令本身当成 `whoami`。
- Tauri 窗口未启动（按规则只做 `cargo check` 和命令行宿主）。
