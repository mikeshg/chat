# A13 交付：工具注入通道 + 读取当前会话历史

对应 Gitea issue `xiefan/chat#11`。无迁移（任务单明确不需要）。

## 1. 实现摘要

### 服务端

- `server/src/auth.rs`：`Claims` 增加 `kind: Option<String>`（序列化时 None 不写出，老 token 形状不变）；`verify_access` 对一切带 `kind` 的 token 一律拒绝——调用凭据无法通过 `require_user`/`require_auth`。新增 `InvocationClaims`（`kind="invocation"`、`sub`=调用 id、`owner`、`agent`、`depth`、`iat`、`exp`）、`mint_invocation`（HS256 + `jwt_secret`，不落库，exp 6h 仅兜底）、`verify_invocation`（`leeway=0`，短命凭据不宽限）。
- `server/src/agent_tools.rs`（新文件）：
  - `require_invocation`：`Authorization: Invocation <token>` 验签与 kind → 查库 `agent_invocations ⋈ conversations ⋈ users`——调用存在、状态为 `running`/`awaiting_approval`、claims 的 owner/agent 与库行一致、主人未禁用；任一不满足 → 401（统一文案，不给探测线索）。
  - `GET /v1/agent-tools/history?before_seq=&limit=`：固定读发起调用的会话（无会话参数可构造越权），额外校验主人仍是成员（403）；复用 `domain::messages_before`/`messages_latest` 读模型，`limit` 默认 50 封顶 200；`ToolMessage {seq, sender_name, is_agent, created_at, content, attachment?}`——附件给 `文件名 (mime)` 占位描述。
- `server/src/agents.rs`：`dispatch` 里为 `running` 调用签发 `tools_token` 写进 `invocation_start` 帧；签发失败按 `token_mint_failed` 置 failed。
- `server/src/api.rs` / `lib.rs`：挂 `/agent-tools/history` 路由与新模块。
- 凭据生命周期：不建撤销表——`finished_at IS NOT NULL`（succeeded/failed/cancelled/timed_out 都置）即失效；宿主断线、主人禁用也走同一查库路径失效。

### AgentHost（`agent-host/`）

- `Cargo.toml`：新增正式依赖 `axum` 0.8 + `reqwest`（rustls-tls、json；无默认特性）。
- `src/mcp.rs`（新）：`McpServer::start()` 同步起本地服务（`127.0.0.1:0`，std listener 转 tokio），`register(server, token) -> McpHandle` 生成随机路径 `/mcp/<id>` 并登记 `（服务端基址, tools_token）` 内存映射；`McpHandle` 的 Drop 摘映射——调用任务结束/被 abort（取消、宿主 shutdown）都会触发，此后该路径一律 404。凭据不出现在 URL/参数里。
  - MCP 方法：`initialize`（回 protocolVersion + `capabilities.tools` + serverInfo）、`notifications/initialized`（及一切无 id 的通知）→ 202、`tools/list`、`tools/call`；未知方法 -32601、未知工具 -32602、坏 JSON -32700、工具执行失败走 `isError:true` 结果。
  - 工具表 `static TOOLS: &[ToolDef]`（name/description/inputSchema/call），后续票往里加条目即可。首个工具 `read_conversation_history`：`GET /v1/agent-tools/history`（`Authorization: Invocation`）→ 格式化成 `[seq N] 发送者: 正文`，Agent 消息带 `(Agent)` 标记，附件追加 `[附件: …]`，`has_more` 时提示用 `before_seq` 翻页。
- `src/mcp_bridge.rs`（新）：`run(url)`——stdin 每行一个 JSON-RPC 消息 → `POST <url>` → 有响应体写回 stdout 一行；通知（202 无体）静默；POST 失败且入站带 id 时回 JSON-RPC error；日志只走 stderr，stdout 纯协议。
- `src/bin/agent-mcp-bridge.rs`（新）：`agent-mcp-bridge <mcp-url>` 薄壳。
- `src/runtime.rs`：`RunRequest.mcp_servers: Vec<InjectedMcp>`；`InjectedMcp{name, http_url, bridge}`。说明：任务单字面写「构造好的 ACP mcpServers 数组」，但 http/stdio 定型必须等 `initialize` 响应里的能力位（在 acp.rs 内），所以 RunRequest 携带的是「注入描述」，`acp.rs` 在 session/new 前落成任务单规定的两种条目形状之一。
- `src/acp.rs`：`mcp_entries(init, injected)`——`agentCapabilities.mcpCapabilities.http` 为真 → `{"type":"http","name":"chat","url","headers":[]}`；否则有桥接 → `{"name":"chat","command":<程序>,"args":[…, "<url>"],"env":[]}`；都不行 → 不注入 + warn，调用照常。
- `src/conn.rs`：`invocation_start` 取 `tools_token`，有本地服务则 register 映射、组 `InjectedMcp{name:"chat"}`，`McpHandle` move 进调用任务保活；本地服务没起来（或帧里没 token）→ 不注入。
- `src/lib.rs`：`pub mod mcp; pub mod mcp_bridge;`、`HostConfig.mcp_bridge: Option<(String, Vec<String>)>`、`Shared.mcp`（spawn 时起）。
- `examples/host.rs`：`--mcp-stdio-bridge <url>` 时进程退化为桥接；宿主 `mcp_bridge = (current_exe, ["--mcp-stdio-bridge"])`。
- `tests/fake-acp-agent.mjs`：`--mcp=http|stdio` 控制 `initialize` 的 `agentCapabilities.mcpCapabilities.http`；`session/new` 存 `mcpServers`；指令 `tool:read_history` → http 直连 `fetch` 或拉起桥接子进程走 stdio JSON-RPC，`tools/call read_conversation_history` 结果原样回出。

### Tauri 桌面端

- `src/main.rs`：`--agent-mcp-bridge <url>` 拦截 → `tauri::async_runtime::block_on(mcp_bridge::run)` 后退出，不起窗口。
- `src/agent_host.rs`：`HostConfig.mcp_bridge = (current_exe, ["--agent-mcp-bridge"])`。

## 2. 接口契约

### JWT claims（tools_token）

`{kind:"invocation", sub:<invocation_id>, owner:<user_id>, agent:<agent_id>, depth:0, iat, exp}`（HS256，与 access token 同 `jwt_secret`；`exp` 6h 兜底，真生命周期由调用状态管）。

### WS 帧

`invocation_start` 增加 `tools_token` 字段（旧宿主代码忽略未知字段，兼容）。

### REST

`GET /v1/agent-tools/history?before_seq=&limit=`，鉴权 `Authorization: Invocation <tools_token>` → `{messages: ToolMessage[], has_more}`；失败一律 401（成员校验例外为 403，与既有 `require_member` 语义一致）。

### 本地 MCP（127.0.0.1:<随机端口>/mcp/<id>）

`POST` JSON-RPC（直接 JSON 响应，无 SSE）：`initialize` / `notifications/initialized` / `tools/list` / `tools/call`；映射摘除后 404。

### ACP `session/new` mcpServers

http 形态 `{"type":"http","name":"chat","url","headers":[]}`；stdio 形态 `{"name":"chat","command":<桥>,"args":[…,"<url>"],"env":[]}`。

## 4. 未覆盖项与已知限制

- 其余工具（调 Agent A14、搜索/读其他会话/发消息 A16、定时 A17）、工具审批与权限档（A12/A16）：任务单明确不做，工具表已留扩展位。
- 调用凭据只在 `running`/`awaiting_approval` 有效；`exp` 6h 只是兜底，不是主生命周期。
- MCP 服务只覆盖任务单列的 4 个方法、单条请求（不批处理、无 SSE session）；真实 ACP agent 走 Streamable HTTP 时按此子集交互足够。
- `RunRequest.mcp_servers` 用 `InjectedMcp` 描述而非成品 ACP 数组（定型依赖 `initialize` 能力位），session/new 产出的条目形状与任务单一致。
- Tauri 桥接入口（`--agent-mcp-bridge`）只经 `cargo check` 验证，未在真桌面壳里跑过 Agent；宿主库层两种注入形态已被 `agent-host` 测试覆盖。
