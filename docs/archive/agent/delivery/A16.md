# A16 交付：搜索 / 读取其他会话 + 以 Agent 身份发消息

对应 Gitea issue `xiefan/chat#17`。无迁移。

## 1. 实现摘要

### 服务端

- `server/src/agent_tools.rs`：`GET /v1/agent-tools/conversations` 列主人参与的会话（标题规则与客户端 `convTitle` 相同：群名 / 私聊对方昵称 / 文件传输助手 / Agent 名），按最近活跃排序，最多 200。`GET /v1/agent-tools/search` 复用全局搜索。`GET /v1/agent-tools/conversations/{id}/messages` 复用 A13 的历史页。`POST /v1/agent-tools/messages` 以当前调用的 Agent 身份发消息。`POST /v1/agent-tools/files` 增加可选 `conversation_id`（缺省仍是发起调用的会话）；主人不是成员则 403。
- `server/src/api.rs`：挂上上述四个路由。

### AgentHost

- `agent-host/src/mcp.rs`：工具表增加 `list_conversations`、`search_messages`、`read_conversation`、`send_message`。`send_message` 的 `file_paths` 先上传到目标会话再发。`read_only`（以及空档位）先走审批；`workspace` / `full` 直接发。登记映射的 `register_with` 带上档位和审批通道。
- `agent-host/src/conn.rs`：`invocation_start` 时把该调用的 `permission_tier` 和 A12 审批通道写进 MCP 映射。
- `agent-host/tests/fake-acp-agent.mjs`：`tool:list`、`tool:search:<关键词>`、`tool:read:<会话id>`、`tool:send:<会话id>:<正文>`、`tool:sendfile:<会话id>:<文件名>:<内容>`（先写临时文件再经 `file_paths` 发）。
- `agent-host/tests/mcp.rs`：工具描述、只读档拒绝不发消息、workspace/full 直接发。
- `server/tests/it.rs`：`// ===== Agent A16 =====` 七个集成测试。

## 2. 接口契约

鉴权一律 `Authorization: Invocation <tools_token>`，范围是主人本人。调用结束、伪造、普通 access token 都是 401。

### REST

`GET /v1/agent-tools/conversations`

```json
[{ "id": "...", "kind": "group", "title": "项目群", "member_count": 2, "last_seq": 1, "readonly": false }]
```

`kind` 是 `group` / `dm` / `self` / `agent`。`readonly`：私聊且对方已不是好友，或 Agent 已删除。按最近一条消息时间（没有消息则用会话创建时间）倒序，最多 200。

`GET /v1/agent-tools/search?q=&limit=`

```json
[{ "conversation_id": "...", "conversation_title": "项目群", "seq": 1, "sender": "显示名", "is_agent": false, "created_at": "...", "text": "..." }]
```

`q` 必填、1–100 字，否则 400。`limit` 默认 30、上限 100（与现有全局搜索一致；任务单没有写死数字）。不返回 `has_more`。只搜主人当前是成员的会话里未删除的消息。

`GET /v1/agent-tools/conversations/{id}/messages?before_seq=&limit=`

与 `GET /v1/agent-tools/history` 相同：`{ messages, has_more }`，字段是 `seq` / `sender_name` / `is_agent` / `created_at` / `content` / `attachment?`。`limit` 默认 50、上限 200。主人不是成员（含会话不存在）403 `not a member of this conversation`。

`POST /v1/agent-tools/messages`

```json
{ "conversation_id": "...", "text": "直发一条", "attachment_ids": ["..."] }
```

响应 `{ "message_id": "..." }`。以当前调用的 Agent 身份发送（`sender_id` 仍是主人，`agent` 是这个 Agent）。主人不是成员 403；只读私聊沿用现有拒绝，403 `好友关系已解除，会话只读`。`attachment_ids` 必须是本次调用上传、且上传时 `conversation_id` 就是目标会话、还没被用过；否则 400（`attachment not from this invocation` / `attachment belongs to another conversation` / `attachment not found` / `attachment already sent` / `duplicate attachment`）。

多个附件时，第一条消息带上正文（可以是空，变成文件消息），其余附件各成一条文件消息。响应里的 `message_id` 是第一条。没有正文也没有附件则 400。

`POST /v1/agent-tools/files?conversation_id=`

查询参数可选。缺省 = 发起调用的会话。指定了则附件归属该会话，主人必须是成员，否则 403。其余行为与 A05 相同（配额、413、调用结束后 401）。

### MCP

| 工具 | 参数 | 说明 |
|---|---|---|
| `list_conversations` | 无 | 易读文本，一行一个会话 |
| `search_messages` | `query`、`limit?` | `[seq N] 标题 / 发送者: 正文` |
| `read_conversation` | `conversation_id`、`before_seq?`、`limit?` | 与读当前会话历史同一格式 |
| `send_message` | `conversation_id`、`text`、`file_paths?` | 成功为 `已发送 message_id=...` |

描述写明：只能访问主人参与的会话；发消息会以 Agent 身份出现。

`send_message` 在 `read_only` 时先发 A12 的 `approval_request`：

```json
{
  "tool_call": {
    "title": "发消息到「项目群」：正文前80字",
    "kind": "send_message",
    "locations": []
  },
  "options": [
    { "optionId": "allow_once", "name": "本次允许", "kind": "allow_once" },
    { "optionId": "reject_once", "name": "拒绝", "kind": "reject_once" }
  ]
}
```

正文按 Unicode 标量取前 80 个。批准（选项 kind 含 `allow` 且不含 `reject`）后才发。拒绝或未识别的选项返回工具错误「主人拒绝了发送」，不发消息。`workspace` / `full` 不审批。卡片仍由 A12 写进该 Agent 的专属会话；`send_message` 不在内置动词表里，卡片摘要是「请求操作：」加上上面的 title。

### 与任务单不一致处

- 搜索的 `limit` 默认 30、上限 100，跟着现有 `GET /v1/search`，任务单没有另给数字。
- 一次 POST 可以带多个附件，响应仍然只有一个 `message_id`（第一条）。任务单的响应形状就是单数。

### 一次真实调用样例

集成测试里 `POST /v1/agent-tools/messages`（凭据已换成占位，不记录 JWT）：

请求：

```http
POST /v1/agent-tools/messages
Authorization: Invocation <tools_token>

{
  "conversation_id": "055a22cf-524e-4de6-b8ee-be367608a588",
  "text": "直发一条",
  "attachment_ids": ["9249dc79-0de7-4ded-b8d3-09d53b25ed3e"]
}
```

响应 `200`：

```json
{ "message_id": "7012d708-6ff0-458b-84b4-32d0a88d4069" }
```

群里随后出现这条 Agent 消息，附件就是上面的 id。

## 4. 未覆盖项与已知限制

- 没有为「超过 200 个会话」造数据；上限在查询里是 `LIMIT 200`。
- 编辑 / 删除已发消息、给主人未参与的会话发消息：任务单明确不做。
- 搜索响应没有 `has_more`。要翻页只能把 `limit` 加大（上限 100）。
- 假 agent 的 `tool:search:<词>` 自己的指令文本也含这个词，所以这条指令总会把自己搜出来。空结果由 REST `q=zzzznotfound` 覆盖。
- 审批等待没有单独超时，和 A12 一样，一直停到主人决定、取消或宿主断开。
- 没有审批通道时（单测里的两参数 `register`）只读档发消息直接失败，不会悄悄发出去。

## 5. 发现的其他问题（范围外）

- `agent-host/tests/registry_cache.rs` 的临时目录用「进程号 + 当前纳秒」命名。Windows 上时钟分辨率较粗时，并行的两个测试可能落到同一目录。第一次 `cargo test` 因此把 `fetch_failure_falls_back_to_stale_cache` 读成了另一个测试写入的 `from-cache`。本票没改登记表代码，重跑即过。
- `app/src-tauri/gen/schemas/desktop-schema.json` 与 `windows-schema.json` 在 `cargo check` 之后被标成已修改；忽略换行后没有内容差异。没有改这些文件的内容。
- `agent-host/tests/files.rs` 里 `Up.name` 未读，是原有警告，不是这次引入的。
