## 2. 接口契约

### 表 `agent_contexts`

| 列 | 说明 |
|---|---|
| `agent_id` | `uuid NOT NULL → agents(id) ON DELETE CASCADE` |
| `context_key` | `text NOT NULL`。本票是发起调用的会话 id（小写带连字符的 uuid 字符串） |
| `runtime_session_id` | `text NOT NULL` |
| `updated_at` | `timestamptz NOT NULL DEFAULT now()` |
| 主键 | `(agent_id, context_key)` |

### REST

`POST /v1/conversations/{id}/agent-context/reset`，无请求体。

- 成员且会话类型是 `agent`：删除对应行，**204**（没有行也是 204）。
- 非成员：**403** `not a member of this conversation`。
- 成员但不是 agent 会话：**400** `not an agent conversation`。
- 会话不存在：没有成员关系，同样 **403**（与调用历史接口一致）。

### WS

- 服务端 → 宿主 `invocation_start` 增加 `context: { key, session_id }`。`key` 是会话 id 字符串；还没有记住的运行时会话时 `session_id` 为 `null`。
- 宿主 → 服务端 `invocation_finish` 在 `ok: true` 时增加 `session_id`（本次实际使用的运行时会话 id）。`ok: false` 不带该字段。服务端只在成功且 `session_id` 非空时 upsert；失败不会覆盖已有行。

### 宿主

- `RunRequest.resume_session: Option<String>`
- `RunOutput.session_id: Option<String>`
- `initialize` 之后：`resume_session` 有值且 `agentCapabilities.sessionCapabilities.resume` 存在（且不是 `false` / `null`）→ `session/resume`，参数 `sessionId`、`cwd`、`mcpServers`（本票仍是空数组）。
- 否则 `loadSession === true` → `session/load`（同样三个参数）。响应返回之前的 `agent_message_chunk` 丢弃。
- 都不支持，或 resume / load 返回错误 → `session/new`，这次调用不算失败。
- 每次调用仍然新起进程。

与任务单无契约偏差。失败帧不附带 `session_id` 是可选字段的一种用法，服务端对失败帧本来也不更新。

## 4. 未覆盖项与已知限制

- 调用方自选上下文号（A14）、群/私聊里的独立上下文（A11）、长驻 agent 进程：未做。
- `session/new` 与恢复请求里的 `mcpServers` 仍是空数组（A13）。
- 「开新话题」分隔只存在当前页面状态里，刷新或换端不会再出现。
- resume / load 失败后退回的新会话如果这次 prompt 成功，服务端会把记住的 id 换成新会话（避免永远卡在坏 id 上）。失败的 prompt 不会换。
