## 2. 接口契约

没有新的 REST、WS 帧或表。冒烟打的是已经合并的接口，和交付文档 A01–A17 一致：

- `GET /v1/admin/settings` 的 `agent_enabled`。若是 `false`，`PUT` 成 `true`，并且不再改回去（否则普通用户在 phase2 读 Agent 接口会 403）。这次跑的时候开关本来就是开的。
- `GET /v1/agent-hosts` 在握手前为空。伪造宿主 id 建 Agent → 404。
- `GET /v1/ws/ticket` 之后连 `/v1/ws?ticket=…&role=host`，发 `host_hello`（`install_id` / `label` / `platform`），等 `host_ready`。自定义命令 `{command,args}` 建 `e2ebot` → 200。会话列表出现 `kind=agent` 的专属会话。
- `PATCH /v1/agents/{id}` 改名、`output_mode=status`、`queue_timeout_secs=120`，列表读回一致；同名再创建 → 409 `name_taken`。提及检查要用 `@e2ebot`，所以改名验证之后又改回 `e2ebot`。
- 群里 B 发 `@e2ebot hi`，该群的 `GET /v1/conversations/{id}/agent-invocations` 条数不变。A 发同一句且宿主在线 → 多一条 `running`。关掉宿主连接后变为 `failed` / `host_disconnected`。
- `PUT` 再 `GET /v1/users/me/agent-settings`：`output_mode=steps`、`max_call_depth=4`，排队超时与 PUT 响应一致。
- `PUT /v1/admin/users/{id}/agent-access` `{allowed:false}` → B 的 `GET /v1/agents` 403 `agent_access_denied`，`GET /v1/users/me` 的 `agent_access=false`。再 `{allowed:null}` 恢复跟随默认：用户列表里覆盖是 `null`，生效值回到当时的全局默认（这次是 `true`）。
- `DELETE /v1/agents/{id}` → 204。列表不再包含 `e2ebot`，专属会话仍在且 `agent.deleted=true`，再发消息得到错误帧 `agent_deleted`。

和任务单字面的一处差别：第 7 步删掉了 `e2ebot`，phase2 若只看 `GET /agents` 就看不到它。因此另建了一个不删除的 `e2ekeep`（同一宿主、自定义命令）。phase2 同时检查：`e2ekeep` 仍在且宿主 id 不变；`e2ebot` 的专属会话仍在且仍是已删除；宿主行的 `label` / `platform` 仍在；个人设置三个字段仍在。

## CONTEXT 改动

| 原说法 | 现说法 | 原因 |
|---|---|---|
| 专属会话里有「被其他 agent 调用」的记录 | 有被调用的记录 | 同一主人名下可以再调用正在跑的同一个 Agent，靠深度上限停住。「其他」把自己排除了 |
| 调用来源是主人 @、另一个 Agent 或定时调用 | 主人在专属会话里发消息，或在私聊 / 群里 @；以及另一个 Agent、定时调用 | 专属会话里直接发消息就是调用，不必写 @ |
| 每个会话各一条上下文，可重置 | 专属会话一条，可以重置；私聊、群、定时调用各自另有一条 | 重置只对专属会话成立。定时调用用自己的上下文，不跟目标会话混用 |
| 权限档位「如只读、可改工作目录、完全放开」 | 三档写死，可改工作目录含额外标明的目录 | `workspace` 自动放行的写入范围是工作目录和额外目录 |
| 审批时主人允许或拒绝 | 主人从该请求给出的选项里决定 | 选项由 agent 给出，包含本次允许、总是允许、拒绝，不是固定两个按钮 |
| Agent 只能调用同一主人的其他 Agent | 只能调用同一主人名下的 Agent | 同上，自己也在范围内；别人的 Agent 仍然不行 |
| 手打 @ 优先解析为自己的 Agent；名字在主人名下唯一 | 补上不区分大小写 | 唯一索引和 @ 匹配都按小写比较 |
| 关掉功能或禁止某用户后入口消失 | 主语收成被关掉或被禁止的非管理员 | 管理员在全局关闭时仍然可用。下一句本来就写了管理员始终可用，这里避免读成管理员自己的入口也消失 |
