# Agent 接入 spec

> 来源：Gitea issue xiefan/chat#1（2026-09-26）。票 A01–A18 = issue #2–#19。

## Problem Statement

我在几台电脑上装了 Claude Code、Codex 这类本地 agent，但只能坐在那台电脑前、在终端里用。人不在电脑前时（在手机上、在另一台电脑上、在群里讨论时），没法让它们干活，也看不到它们的进度。agent 之间也没法互相协作：coding 需要资料时不能直接找 research，Windows 上的 agent 叫不动 Mac 上的 agent。

聊天软件已经是我在所有设备上都开着的东西，但 v1 规划明确把「Bot 平台」列为以后单独立项，现在的产品里完全没有 agent 的概念。

## Solution

在聊天软件里加入 **Agent**。每个 Agent 属于一个用户，固定在该用户的某台桌面端（**AgentHost**：Windows / macOS / Linux）上运行，背后是一个本地 **AgentRuntime**（Claude Code、Codex 等任何支持 ACP 协议的 agent，将来还有内置 agent）。

- 在任意客户端（Web、Android、桌面）都能管理自己所有的 Agent，并用 `@research 研究一下今天有哪些新闻` 这种方式调用。
- 每个 Agent 有一个 **AgentConversation**（专属会话，只有主人和它）；也可以在主人所在的任意私聊或群里 @ 它，回复出现在原会话，成员都能看到。
- 只有主人能调用自己的 Agent。
- Agent 以自己的名字和头像发言，工作过程可以实时流式显示、只显示状态和结果、或每步一条消息，可配置。
- Agent 要做超出 **PermissionTier** 的操作时，在专属会话里给主人发 **Approval** 卡片，主人在任意客户端批准。
- 宿主离线时调用会排队，上线后执行，超时自动取消。
- 桌面端会给每个 Agent 注入一组聊天工具：调用主人的其他 Agent（同步或异步）、读取当前会话历史、搜索/读取主人的其他会话、往主人的其他会话发消息、创建 **ScheduledInvocation**。
- 管理员可以在后台控制 **AgentAccess**：全局开关 + 全局默认 + 逐用户覆盖。

## User Stories

**宿主与添加 Agent**

1. 作为桌面端用户，我希望桌面端首次启动时自动成为一个 AgentHost，并有一个不随登录变化的永久标识，这样退出重登、改密码后我的 Agent 不会丢。
2. 作为桌面端用户，我希望给 AgentHost 起个名字（如「家里 Windows」「MacBook」），这样在其他客户端能分清 Agent 跑在哪台电脑上。
3. 作为用户，我希望在任意客户端看到我所有 AgentHost 的在线状态，这样知道现在能不能立刻调用某个 Agent。
4. 作为用户，我希望在任意客户端（包括手机）给某台 AgentHost 添加 Agent，这样不用坐在那台电脑前。
5. 作为用户，我希望添加 Agent 时能从 ACP 官方登记表里选运行时，并看到它在目标宿主上装没装，这样不用记启动命令。
6. 作为用户，我希望对没装的登记表 agent，确认后由宿主机自动安装，这样在手机上也能完成添加。
7. 作为用户，我希望登记表里没有的 agent 可以手填启动命令和参数，这样任何支持 ACP 的程序都能接进来。
8. 作为用户，我希望给 Agent 设一个名字（用来 @）和头像，名字在我名下唯一，这样 @ 时不会有歧义。
9. 作为用户，我希望给 Agent 设工作目录和额外可访问目录（宿主机上的路径），这样 coding 类 agent 在正确的项目里工作。
10. 作为用户，我希望按运行时提供的选项选模型/模式，这样同一种 agent 可以配成不同用途。
11. 作为用户，我希望给 Agent 写附加指令（系统提示词），这样 research 和 coding 可以有不同的行为风格。
12. 作为用户，我希望给 Agent 设环境变量（包括 API key），并能在任意客户端修改，这样需要密钥的 agent 也能用。
13. 作为用户，我希望修改 Agent 的任意配置都能在任意客户端完成，并在宿主上生效，这样管理不受地点限制。
14. 作为用户，我希望删除 Agent 后它的专属会话保留为只读，这样历史记录不会丢。
15. 作为用户，我希望 Agent 的宿主在添加时选定且之后不能改，这样不会出现上下文错乱；换电脑时我重新添加即可。
16. 作为桌面端用户，我希望关掉窗口后客户端驻留托盘继续当宿主，这样 Agent 不会因为关窗口而离线。
17. 作为桌面端用户，我希望可以选择开机自启，这样电脑重启后 Agent 自动上线。
18. 作为 macOS 和 Linux 用户，我希望也有桌面端安装包并能当宿主，这样我的 Mac 也能跑 Agent。

**调用**

19. 作为用户，我希望在 Agent 专属会话里直接发消息就是在调用它，这样和它聊天像和联系人私聊一样。
20. 作为用户，我希望在我所在的任意私聊或群里用 `@名字 指令` 调用我的 Agent，回复出现在这个会话里，这样可以把结果直接展示给群成员。
21. 作为用户，我希望在输入 @ 时，补全列表同时列出群成员和我的 Agent（Agent 有明显标记和在线状态），选中谁就是谁，这样同名时也不会 @ 错。
22. 作为用户，我希望手打 `@名字` 没从补全里选时，优先当作我自己的 Agent，这样快速输入也能调用。
23. 作为群成员，我希望别人 @ 我的 Agent 不会触发它，这样别人不能借我的 Agent 在我电脑上执行命令。
24. 作为用户，我希望把图片和文件连同指令一起发给 Agent，图片直接给模型看、文件放到宿主机上供它读取，这样它能处理我的材料。
25. 作为用户，我希望 Agent 产出的文件（报告、截图、压缩包）作为附件发回会话，计入我的存储配额，这样我在手机上也能拿到结果。
26. 作为用户，我希望同一个 Agent 被多处同时调用时并行运行，这样不会互相等待。

**上下文**

27. 作为用户，我希望 Agent 在同一个会话里记得之前聊过的内容（专属会话一条，每个私聊/群各一条），这样可以追问「把第 3 条展开」。
28. 作为用户，我希望能在某个会话里让 Agent「开新话题」，清空这个会话的 AgentContext，这样不相关的话题不会互相干扰。
29. 作为用户，我希望在群里 @ Agent 时它默认只看到我 @ 它的那条消息，需要时再用工具读取会话历史，这样不浪费 token，也减少被别人消息诱导的机会。

**输出与状态**

30. 作为用户，我希望 Agent 以自己的名字和头像发言，并带 Agent 标记，这样和真人消息区分开。
31. 作为用户，我希望 Agent 的回复算作未读、会触发通知和推送（我自己也会收到），这样长任务做完我能及时知道。
32. 作为用户，我希望可以选择「实时流式」输出：一条回复边生成边更新，上方显示正在做的步骤，可折叠，这样能实时看进度。
33. 作为用户，我希望可以选择「状态 + 最终结果」输出：过程中只显示「正在工作 · 已用 3 分钟 · 当前步骤」，完成后发一条结果，这样群里不刷屏。
34. 作为用户，我希望可以选择「每步一条消息」输出，这样每个步骤都留有独立记录。
35. 作为用户，我希望在个人设置里设默认输出方式，并能对每个 Agent 单独覆盖，这样不同 Agent 用不同的显示方式。
36. 作为用户，我希望流式过程结束后，定稿消息里仍保留可折叠的步骤记录，这样事后能回看它做了什么。
37. 作为群成员，我希望看到 Agent 回复的当前状态（排队中 / 运行中 / 等待主人批准 / 完成 / 失败 / 已取消 / 已超时），这样知道结果还来不来。
38. 作为用户，我希望在任意客户端取消一个排队中或运行中的调用，连带取消它派出的子调用，这样能及时止损。
39. 作为用户，我希望宿主客户端退出或崩溃时，进行中的调用被标记为失败并说明原因，这样不会一直显示运行中。

**权限与审批**

40. 作为用户，我希望给每个 Agent 设 PermissionTier（只读 / 可改工作目录 / 完全放开），档位内的操作自动放行，这样长任务不会被频繁打断。
41. 作为用户，我希望 Agent 要做超出档位的操作时，在它的专属会话里给我发 Approval 卡片，写清具体命令或文件路径，这样我人不在电脑前也能决定。
42. 作为用户，我希望在任意客户端点「本次允许 / 总是允许 / 拒绝」（按 agent 提供的选项），Agent 等我决定后继续，这样审批不受地点限制。
43. 作为群成员，我希望在群里调用 Agent 需要审批时，群里只显示「等待主人批准」而不显示命令内容，这样主人电脑上的信息不会泄露给群。
44. 作为用户，我希望审批卡片触发通知，这样我能尽快处理，Agent 不会一直卡着。
45. 作为用户，我希望「往其他会话发消息」这类操作也受 PermissionTier 管，超出档位就要审批，这样 Agent 不会擅自在群里发言。

**宿主离线**

46. 作为用户，我希望宿主离线时调用先在服务器排队，宿主上线后自动执行，这样不用等电脑开机再重新发。
47. 作为用户，我希望排队中的调用显示「排队中：宿主离线」，并能手动取消，这样心里有数。
48. 作为用户，我希望排队超过设定时长自动取消（时长可在个人默认和每个 Agent 上设置，可设永不），这样几天前的指令不会突然执行。

**Agent 互调**

49. 作为 Agent，我希望通过注入的工具调用主人的其他 Agent（包括其他宿主上的），这样能把子任务交给更合适的 Agent。
50. 作为 Agent，我希望调用时可以选择等待结果，或者拿到调用号先去干别的、之后再查询或等待，这样能同时派出多个 Agent 并行干活。
51. 作为 Agent，我希望每次调用返回一个上下文号，下次带上就接着上次聊，不带就新开，这样能对同一个子 Agent 追问。
52. 作为用户，我希望被调用的 Agent 用它自己的 PermissionTier，审批发到它自己的专属会话，这样权限不会因为互调被放大。
53. 作为用户，我希望互调深度有上限（在个人设置里配置），超过就拒绝，这样 Agent 之间不会无限互相调用。
54. 作为用户，我希望在原会话里把子调用显示成可展开的嵌套卡片，能看到子 Agent 的过程和结果，这样看得懂整件事是怎么做的。
55. 作为用户，我希望被调用的 Agent 的专属会话里留一条「被 X 调用」的记录，这样事后能查它替谁干过什么。
56. 作为用户，我希望调用离线宿主上的 Agent 时按同样规则排队，这样互调和我手动调用行为一致。

**注入的聊天工具**

57. 作为 Agent，我希望能读取当前会话的历史消息，这样能完成「总结一下上面的讨论」。
58. 作为 Agent，我希望能搜索和读取主人参与的其他会话，这样能完成「把昨天项目群里定的事整理成清单」。
59. 作为 Agent，我希望能以自己的身份往主人参与的其他会话发消息，这样能完成「做完把结论发到项目群」。
60. 作为 Agent，我希望能创建、查看、删除 ScheduledInvocation，这样能完成「每天 9 点汇总新闻发到这里」。
61. 作为用户，我希望注入工具的可见范围和我本人完全一致（看不到我没参与的会话），这样 Agent 不会越权。

**定时调用**

62. 作为用户，我希望在界面上给某个 Agent 建定时调用（时间表、指令、结果发到哪个会话），这样例行任务自动跑。
63. 作为用户，我希望查看、暂停、删除我的定时调用，这样能管理例行任务。
64. 作为用户，我希望定时调用到点时宿主离线，就按离线规则排队和超时，这样行为可预期。

**管理员**

65. 作为管理员，我希望在后台有一个全局开关控制 Agent 功能，这样可以整体停用。
66. 作为管理员，我希望设置全局默认（新用户默认允许或禁止使用 Agent），这样开放注册的服务器也能控制风险。
67. 作为管理员，我希望在用户列表里逐个用户覆盖 AgentAccess，这样能单独放行或禁止某些人。
68. 作为管理员，我希望自己始终能用 Agent，这样不会把自己锁在外面。
69. 作为用户，我希望失去 AgentAccess 后 Agent 入口消失、新调用被拒绝、进行中的调用被取消，我的 Agent 配置和历史保留，恢复权限后照常使用。
70. 作为管理员，我希望备份和恢复包含所有 Agent 相关数据，这样恢复后 Agent 配置不丢。

## Implementation Decisions

**总体架构**

- 三块：服务端（数据、调用排队与分发、权限校验、注入工具的后端接口）、宿主运行时（桌面端里跑 Agent 的部分）、前端（所有客户端共用的管理与展示界面）。
- 宿主运行时做成一个**不依赖 Tauri 界面的 Rust 库**，Tauri 桌面端只负责启动它、提供托盘和本地存储路径。这样测试可以直接驱动真宿主。
- 接入方式：**ACP 为主，必要时原生**。宿主运行时定义一个 Agent 抽象（开始/恢复上下文、发指令、事件流、权限请求、取消），首个实现是 ACP 客户端；只有当某个 CLI 的关键能力 ACP 适配器没暴露时，才给它写原生实现。将来的内置 agent 也按 ACP agent 实现。
- ACP 映射：`session/new` 带工作目录和 mcpServers（注入聊天工具）；`session/load` 或 `session/resume`（按 agent 声明的能力）实现 AgentContext 延续；`session/prompt` 发指令，图片作为内容块、文件作为资源路径；`session/update` 转成输出事件；`session/request_permission` 先对照 PermissionTier，档位内自动选允许，超出的转成 Approval；`session/cancel` 实现取消。
- 与现有架构一致：服务端单实例，宿主分发依赖内存里的连接表（README 已声明只跑一个实例）。

**数据模型（服务端）**

- **AgentHost**：所属用户、永久标识（宿主生成）、名称、平台、最后在线时间。同一台电脑换用户登录，是不同用户各自的 AgentHost 记录。
- **Agent**：主人、所在 AgentHost（不可改）、名字（主人名下唯一，不区分大小写）、头像、运行时（登记表条目或自定义命令+参数）、工作目录、额外目录、模型/模式、附加指令、PermissionTier、输出方式覆盖、排队超时覆盖、环境变量（明文）、删除时间。
- **AgentConversation**：新的会话形态，与 SelfConversation 同理：每个 Agent 恰好一个，唯一成员是主人，引用该 Agent；不能拉人、改名、退出；Agent 删除后只读。
- **消息作者**：消息可以由 Agent 发出。Agent 发出的消息不算「主人自己的消息」，未读、@、通知、推送按「别人的消息」处理（主人也会收到）。消息视图带 Agent 标识（名字、头像、主人）以便渲染。主人可以删除自己 Agent 发的消息。
- **AgentInvocation**：Agent、来源（主人 / 另一个调用 / 定时调用）、发起会话、父调用、深度、AgentContext 键、指令与输入附件、状态（排队 / 运行中 / 等待审批 / 完成 / 失败 / 已取消 / 已超时）、失败原因、排队截止时间、结果消息、各时间戳。
- **AgentContext**：Agent + 上下文键（会话 id，或调用方选的上下文号）→ 运行时侧的会话 id（由宿主回报），可重置（重置即丢弃映射）。
- **Approval**：所属调用、请求内容（工具类型、命令/路径摘要）、可选项（按 agent 提供）、决定、决定时间。
- **ScheduledInvocation**：Agent、时间表与时区、指令、结果投递会话、启用状态、下次运行时间。
- **个人 Agent 设置**：默认输出方式、默认排队超时、互调深度上限。
- **ServerSettings** 增加 Agent 全局开关和全局默认；用户上增加可空的 AgentAccess 覆盖。
- 备份/恢复自动包含新表（现有备份按全部表导出）。

**调用生命周期（服务端）**

- 触发：主人在会话里发出带 Agent 目标的消息 → 服务端校验「发送者是 Agent 主人」且主人有 AgentAccess → 为每个目标 Agent 建一个调用。非主人消息里的 Agent 目标一律忽略。
- @ 解析：客户端在消息里显式带上选中的目标（Agent 或用户）；服务端对手打未显式指定的 `@token`，先匹配发送者自己的 Agent，再匹配群成员（延续 ADR-001 §10「服务端解析提及」的原则）。
- 分发：宿主在线 → 立即通过 WS 推给宿主；离线 → 排队，宿主连上时按创建顺序补发。后台定时任务清理超过排队截止时间的调用（标为已超时）。
- 并发：同一 Agent 的调用互不等待。
- 取消：主人在任意客户端取消 → 状态改为已取消 → 通知宿主 → 递归取消所有子调用。
- 宿主断线：该宿主上运行中的调用标为失败（原因：宿主断开）。
- AgentAccess 失效（全局关、用户被禁止、账号被禁用）：拒绝新调用，取消进行中的调用。

**宿主与服务端之间的协议**

- 宿主用主人的登录凭据连 WS，并在连接上声明自己是某个 AgentHost（带永久标识）；服务端据此维护宿主在线状态并广播给主人的所有连接。
- 服务端 → 宿主：开始调用（Agent 配置快照、指令、附件、AgentContext 的运行时会话 id、调用专用凭据）、取消调用、审批结果、配置变更通知。
- 宿主 → 服务端：状态变化、输出事件（文本增量、步骤开始/结束、子调用关联）、审批请求、最终结果（定稿文本、步骤记录、附件）、运行时会话 id 回报。
- 每个调用有一个**调用专用凭据**：绑定主人、Agent、调用 id、深度，调用结束即失效。注入工具只能用它访问服务端，权限范围等于主人本人（仅主人参与的会话）。

**输出（服务端 + 前端）**

- 实时流式：增量只通过 WS 推给会话成员的在线连接，不写库，服务端按时间窗口合并以限制帧率；结束时写一条定稿消息，带可折叠的步骤记录。
- 状态 + 最终结果：过程中只推送状态和当前步骤，结束写一条结果消息。
- 每步一条消息：每个步骤写一条普通 Agent 消息。
- 输出方式取值顺序：Agent 覆盖 → 个人默认。
- 群里调用需要审批时，原会话的状态只显示「等待主人批准」；卡片本身只进 AgentConversation。

**注入的聊天工具（宿主运行时提供的本地 MCP 服务）**

- 宿主为每个调用提供一个本地 MCP 服务，通过 `session/new` 的 mcpServers 交给 agent；工具调用由宿主转成对服务端的请求，使用调用专用凭据。
- 工具清单：
  - 调用 Agent：参数是 Agent 名、指令、是否等待、可选上下文号；返回结果或调用号，以及上下文号。
  - 查询调用 / 等待调用：按调用号查状态或阻塞等待结果。
  - 读当前会话历史：分页读取发起会话的消息。
  - 搜索消息 / 读取会话：复用现有全局搜索和历史分页，范围为主人参与的会话。
  - 发消息：以当前 Agent 身份发到主人参与的某个会话；受 PermissionTier 管，超出走 Approval。
  - 定时调用：创建 / 列出 / 删除。
- 互调规则：被调方必须属于同一主人；深度超过主人设置的上限时拒绝；被调方用自己的 PermissionTier，审批进它自己的 AgentConversation；跨宿主调用经服务端分发，离线照常排队；被调方专属会话写一条「被 X 调用」记录；原会话里作为父调用的嵌套子调用展示。

**PermissionTier 映射（宿主运行时）**

- 只读：自动允许读取、搜索、抓取类操作；其他全部走审批。
- 可改工作目录：在只读基础上，自动允许工作目录和额外目录内的编辑；执行命令和目录外的写入走审批。
- 完全放开：全部自动允许。
- 「发消息」工具：只读档位走审批，其他档位自动允许。
- 能用 ACP 会话模式（如 agent 自带的权限模式）表达档位时，同时设置，减少无谓的权限请求。

**附件**

- 输入：宿主把调用附件下载到该调用的临时目录；图片作为 ACP 图片内容块，其他文件以路径形式交给 agent。
- 输出：agent 通过发消息工具附带宿主本地文件路径，或在最终结果里声明产出文件；宿主上传后作为附件消息发出，计入主人存储配额，超出配额时调用照常结束并说明附件未发出。

**登记表与安装（宿主运行时）**

- 宿主拉取 ACP 登记表，报告每个条目在本机是否可用；主人确认后按条目的分发方式在本机安装；自定义命令不经登记表。
- 安装、启动都在宿主本机进行，服务端只保存 Agent 配置。

**前端**

- Agent 管理页：按宿主分组列出 Agent（在线状态），添加（选宿主 → 选登记表条目或自定义命令 → 配置）、编辑、删除；个人默认设置。
- 会话列表：AgentConversation 像联系人私聊一样出现，显示 Agent 头像和在线状态。
- 输入框：@ 补全加入主人自己的 Agent（带标记和在线状态），消息里显式带上选中的目标。
- 消息渲染：Agent 标记；三种输出方式；可折叠步骤；嵌套子调用卡片；状态标签；主人可见的取消按钮。
- Approval 卡片：显示请求内容和 agent 提供的选项，按钮只对主人可用。
- 定时调用管理：在 Agent 详情里列出、创建、暂停、删除。
- 管理后台：Agent 全局开关、全局默认；用户列表里的 AgentAccess 覆盖。
- 桌面端：托盘驻留、开机自启开关、宿主名称设置；新增 macOS 和 Linux 打包目标。

## Testing Decisions

- **好测试的标准**：只断言客户端能观察到的外部行为（REST 响应、WS 帧、会话里出现的消息、状态变化），不断言内部结构、表字段或宿主的内部状态。
- **主接缝：服务端集成测试 + 真宿主 + 假 ACP agent**。沿用现有服务端集成测试的做法（起测试服务端、注册用户、加好友、建群、连 WS、等待特定帧），再在测试里启动真的宿主运行时库连到测试服务端，Agent 的运行时配置成一个**假 ACP agent**：一个按剧本行事的小程序，能输出流式文本、上报步骤、发权限请求、调用注入的聊天工具、按指令延迟或失败。要覆盖的场景：
  - 主人 @ → 回复出现在原会话，作者是 Agent，其他成员也收到，主人未读数增加
  - 非主人 @ 同一个 Agent → 不产生调用
  - 同名冲突：显式目标优先；手打时先解析为主人的 Agent
  - 三种输出方式各自的帧和最终消息；流式增量不写入历史
  - 超出档位 → Approval 只出现在 AgentConversation，群里只有「等待主人批准」；允许 / 拒绝后 agent 按结果继续
  - 宿主离线 → 排队；宿主上线后执行；排队超时 → 已超时；手动取消
  - 取消运行中的调用连带取消子调用；宿主断线 → 失败
  - 互调：同步等待拿到结果；异步拿调用号后查询/等待；并行派出两个；上下文号续用与新开；深度上限；跨宿主（测试里起两个宿主）；被调方审批进它自己的专属会话；被调方专属会话有「被 X 调用」记录
  - 注入工具的范围：读不到主人没参与的会话；调用结束后调用专用凭据失效
  - AgentContext：同一会话第二次调用带上运行时会话 id；「开新话题」后不再带
  - 附件进出；超配额时附件不发出但调用正常结束
  - 定时调用到点生成调用；宿主离线时排队
  - AgentAccess：全局关 / 默认禁止 / 用户覆盖 / 管理员始终可用；失去权限时进行中的调用被取消
  - 删除 Agent 后专属会话只读
- **迁移测试**：新迁移按现有迁移测试的方式验证（空库迁移、带旧数据迁移）。
- **前端纯逻辑单测（vitest）**：@ 解析优先级、三种输出方式的渲染状态计算、子调用嵌套树的构建。参照现有的 `*.test.ts` 纯函数测试（如会话预览、搜索片段、转发目标的测试）。不测 Tauri 界面。
- **真 agent 冒烟**：一条开关控制、默认不跑的测试，用真的 Claude Code 和 Codex ACP 适配器通过宿主运行时跑一次简单调用（含一次权限请求），验证适配器确实可用。需要本机已登录这两个 CLI，会消耗 token。
- **E2E 脚本**：现有 E2E 冒烟脚本补上不需要宿主的部分：Agent 管理 CRUD、AgentAccess 开关、非主人 @ 不触发。

## Out of Scope

- 内置 agent（将来做，届时按 ACP agent 实现）。
- 让别人调用我的 Agent / 把 Agent 共享给好友或群。
- 把 Agent 搬到另一台宿主（换电脑需重新添加）。
- 加密存储 Agent 的环境变量和密钥。
- Web、Android、iOS 作为宿主（只能管理和调用）。
- 为具体 CLI 写原生（非 ACP）对接，除非实现中发现 ACP 适配器缺关键能力。
- 多服务端实例之间转发宿主调用。
- Agent 调用其他用户的 Agent。

## Further Notes

- v1 规划把「Bot 平台、AI 总结」列为以后单独立项，本 spec 就是那次立项；需求来自 2026-09-26 的一次 grilling（26 个决策）。领域词汇见 CONTEXT.md 的 Agent 小节。
- 已知取舍：
  - 环境变量和密钥明文存服务器，服务器、管理员、备份都能看到（用户明确选择）。
  - 读取类注入工具会把别人的消息交给 Agent，可能被诱导；靠 PermissionTier 和 Approval 兜底。
  - 同一 Agent 的调用总是并行，多个调用同时改同一工作目录可能冲突（用户明确选择）。
  - Claude Code 的 ACP 适配器是 npm 包，宿主机需要 Node。
- 「ACP 为主、原生兜底」的理由和代价见 ADR-001 §12。
- 建议实现分期：服务端数据模型与调用分发 → 宿主运行时（ACP 客户端、托盘、假 agent 测试接缝）→ 输出与审批界面 → 互调与注入工具 → 定时调用 → 管理员控制与 macOS/Linux 打包。
