# P3-1 全局搜索 + 会话「文件与图片」列表 — 交付文档

## 1. 实现摘要

迁移（新增）：

- `server/migrations/0016_search_trgm.sql` — `CREATE EXTENSION IF NOT EXISTS pg_trgm` + 部分 GIN 索引 `idx_messages_content_trgm`（`messages(content) gin_trgm_ops`，`WHERE deleted_at IS NULL`，墓碑行不进索引）。

服务端：

- `server/src/domain.rs` —
  - `like_escape`：`%`/`_`/`\` 转义为字面量（`ESCAPE '\'`，两处搜索共用）。
  - `search_messages`（会话内搜索）改为两段式：先查 `messages`（`conversation_id` + `deleted_at IS NULL` + 转义 ILIKE，`created_at DESC,id DESC`，`limit+1` 算 has_more）得候选 id，再 `messages_by_ids` 取个性化 `MessageView` 并按候选序重排——修好「搜“消息已删除”命中墓碑」的 bug 且可用上 trgm 索引。
  - `SearchFilter` + `search_global`：`messages ⨝ memberships`（成员行即时过滤，退群即搜不到），`deleted_at IS NULL`；支持 `q`（转义 ILIKE）、`conversation_id`/`sender_id`/`kind`/`from`（含）/`to`（不含）筛选与 `(created_at,id) < (before,before_id)` 游标翻页；取 `limit+1` 判 `has_more` 后经 `messages_by_ids` 回填全量视图并按 `created_at DESC,id DESC` 重排（不重不漏）。
- `server/src/api.rs` — 路由 `GET /v1/search` + `GlobalSearchQuery` + `global_search` 处理器：`uid_of` 鉴权 → `q` 去空白、1–100 字符、`kind∈{text,image,file,audio}`、全空参数 400、`conversation_id` 非成员 403（`require_member`）、`limit` 缺省 30 收敛到 1–100 → `search_global` → `{messages, has_more}`。

客户端：

- `app/src/api.ts` — `SearchParams` + `searchApi.messages()`（`GET /v1/search` 查询串构造，空值不下发）。
- `app/src/store.ts` — 新增 `pendingJump: {convId,messageId,seq} | null`（初始 null）。
- `app/src/App.tsx` — logout 复位里补 `pendingJump: null`。
- `app/src/ui/searchSnippets.ts`（新）— 纯函数：`highlightParts`（大小写不敏感、字面量切分、多处命中）、`snippetOf`（附件占位摘要 [图片]/[语音]/[文件] x.x）、`convTitleOf`（conversation_id → 会话目录标题，未知兜底「会话」）、`matchConvsByTitle`（本地会话过滤）、`senderOptions`（好友+会话 peer+已缓存消息发送者去重排序）。
- `app/src/ui/SearchPanel.tsx`（新）— 搜索态列表：类型 chip（全部/图片/文件/语音）+「更多筛选」（发送者下拉 + 原生 date 日期区间，含 from 不含 to 由服务端保证）；上半「会话」区本地标题过滤即点即开；下半「聊天记录」区 300ms 防抖请求 `/v1/search`、`<mark>` 高亮关键词、滚到底用末条 `(before,before_id)` 游标翻页（按 id 去重）、点结果 `pendingJump` + `openConversation`。
- `app/src/ui/ConvList.tsx` — 复用既有搜索框：非空输入切换到 `SearchPanel`，Esc 清空回普通列表。

## 2. 接口契约

- REST 新增：`GET /v1/search`，query：`q`（可空；非空时 trim 后 1–100 字符）、`conversation_id`、`sender_id`、`kind`（text/image/file/audio）、`from`（RFC3339，含）、`to`（RFC3339，不含）、`before`+`before_id`（翻页游标，取上一页末条的 `created_at`+`id`）、`limit`（缺省 30，收敛 1–100）。全部为空 400；非法 kind / q 超长 400；`conversation_id` 非成员 403。返回 `MessagesPage { messages: MessageView[], has_more }`，按 `created_at DESC,id DESC`。
- 与任务单的一致性：参数表、排序、校验、游标语义、两阶段候选→视图回填均按单实现。`before_id` 单独缺省按最小 UUID 处理（等 created_at 的行被排除——客户端总是成对回传，行为与成对游标一致）。
- 会话内搜索 `GET /v1/conversations/{id}/messages/search`：对外契约不变（仍返回 `MessageView[]`），内部改为查 `messages` 表——墓碑不再命中，且可用 `idx_messages_content_trgm`。
- WS：无新帧类型；`send_message`/`message` 不变。
- 表结构：`0016` 新增 `pg_trgm` 扩展与部分 GIN 索引；无列/表改动。

## 4. 未覆盖项与已知限制

- 语音页签：浏览器实测未造真实语音消息（`duration_ms` 走录音上传路径）；列表渲染复用 `AudioBubble`、kind=audio 筛选由 it.rs 覆盖。语音列表项样式简单，风险低。
- 「更多筛选」的发送者候选来自好友 + 会话 peer + 本地已缓存消息发送者；从未出现在本地缓存里的群成员不会出现在下拉中（有 id 时服务端筛选仍正确）。
- 搜索跳转到很老的消息：`jumpToRef` 以 `seq±25` 拉 50 条窗口，落在窗口内即定位；继续上滚可继续 `loadMore`。
- `pg_trgm` 对 ≥3 字符子串收益最大；1–2 字符或超高频词的查询退回部分索引上的顺序过滤，语义不变。
- 搜索结果点击只打开会话+定位，不自动清空搜索框（再输入/ Esc 才退出搜索态，符合任务单「Esc 或清空回到普通列表」）。

## 5. 发现的其他问题（范围外，仅记录）

- 会话内 `ChatView` 顶部小搜索面板（`.search-panel`）结果项未做关键词高亮、无翻页；本任务只要求其服务端语义修好（墓碑排除已实现并回归测试），UI 增强属后续优化。
- `ConvList` 归档页签计数与搜索态并存：输入搜索词后仍显示归档 tab（不影响功能，搜索态替换的仅是列表区）。
- `SearchPanel` 的「会话」区头像对群会话用首字方块、self 用 🗂，与 conv item 逻辑一致但对 dm 无在线点（搜索态不显示在线状态，符合列表信息降噪预期）。
