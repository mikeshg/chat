## 2. 接口契约

### 表结构

未新增迁移（`0012_v2_media.sql` 的 `attachments.width/height/thumb_path` 已够用；未占用 `0013`：配额查询按 `uploader_id` 过滤小结果集、admin 聚合按当前页 ≤50 用户，索引收益不成立）。`message_views` 未改动。

### REST

| 端点 | 语义 |
|---|---|
| `POST /v1/files` | 响应沿用 `AttachmentView`（P2-0 已带 `width/height/has_thumb`），现在如实填充：解码成功 → 宽高；最长边 >480 → `has_thumb=true`、缩略图落盘 `<files_dir>/<att_id>.thumb.jpg`；解码失败/超限 → 字段空、附件照常入库。配额命中 → **413** `{"error":"存储空间已满（已用 X MB / 上限 Y MB）"}`（已用按 0.1MB 精度展示） |
| `GET /v1/files/{id}?thumb=1` | 有缩略图 → `image/jpeg` 缩略图，缓存头与原图一致（`private, max-age=31536000, immutable`）；无/读失败 → 原图；`dl=1` 覆盖 `thumb=1` |
| `GET /v1/users/me/storage` | `{used_bytes, quota_bytes}`；`quota_bytes=null` 表示不限 |
| `GET/PUT /v1/admin/settings` | 增加 `storage_quota_mb`（0-1048576 整数；非法 → 400 `storage_quota_mb 必须是 0-1048576 的整数`；0=不限）。仅管理员可读改 |
| `GET /v1/admin/users` | 每条用户增加 `storage_bytes`（与本人 `used_bytes` 同一聚合口径） |
| `GET /v1/server-info` | 不变，不暴露配额 |

### 删除/共享

`delete_in_tx` 删 attachment 行后，若 `storage_path` 不再被其他行引用（含转发产生的共享行），孤儿清单同时含 `storage_path` 与 `thumb_path`；共享行还在则两者都保留。物理删文件沿用原有异步 `tokio::fs::remove_file`。

### 客户端契约

- 图片气泡：`<img src="/v1/files/{id}?thumb=1">`（`has_thumb` 时）+ `style={width,height}` 按原图等比预留（最长边 240）；预览弹层仍用原图 URL；`dl=1` 下载不变。
- 上传失败（含 413）：`send()` 捕获服务端 `error` 文案显示在 `.pf-err`，不 `alert`，不清待发附件。

与任务单的偏差：无。413 文案格式、配额范围、`ponytail` 注释（并发可略超、如需严格上限按 uploader_id 加锁）、GIF 不缩略、SVG 不处理，均按任务单实现。

## 4. 未覆盖项与已知限制

- **并发配额**：读-改无锁，并发上传可能略超配额（已按任务单加 `ponytail` 注释，未来可按 `uploader_id` 串行化）。
- **GIF**：只记首帧宽高、不出缩略图（保留动图），列表态 `<img>` 仍直接取原图；这是任务单既定行为。
- **EXIF**：取 `image` 解码器报告的 Orientation 并应用到像素；极端/损坏 EXIF 退化为未旋转尺寸，属解码器行为。
- **SVG/其他 mime**：不解析不缩略（安全边界）。
- **配额统计口径**：按 `uploader_id` 行 + `storage_path` 去重，删消息后孤儿文件删掉前仍计入用量（数据一致即准确）。
- **配额 UI 数字精度**：管理页输入框以 MB 为粒度（与服务端单位一致），不支持小数。

## 5. 发现的其他问题（范围外，只记录）

- **`onFile` 附件按钮选择文件后不进待发区**：`ChatView.tsx` `onFile` 先 `e.target.value = ""` 再判 `fl?.length`；Chromium 中 `value=""` 会清空同一个 live `FileList`，`fl.length` 变 0 → `addPending` 永不执行（本次浏览器实测用「粘贴路径」绕过验证，已在页面内 probe 证实 `fl` 变空）。建议把 `e.target.value=""` 移到 `addPending` 之后或先 `Array.from`。
- `onFile` 同样 `readonly` 早退在清 value 之后，只读会话里点 📎 会静默吞掉一次选择（无害但行为不一致，同一处可一起修）。
