# P1-1 系统通知 + 标题未读 + 任务栏提醒 — 交付文档

## 1. 实现摘要（改了哪些文件、各做了什么）

**新增**

- `app/src/notify.ts` — 系统通知模块，唯一对外出口：
  - `notifySupport()`：检测 `"__TAURI_INTERNALS__" in window` → `"tauri"`；否则 `Notification in window` → `"web"`；否则 `"none"`。
  - `notifyPermission()` / `requestNotifyPermission()`：Web 走 `Notification.permission`/`requestPermission()`；Tauri 动态 `import("@tauri-apps/plugin-notification")` 走 `isPermissionGranted()`/`requestPermission()`（Android 13+ 运行时权限经此路径）。
  - `showSystemNotification({title, body, convId, onOpen})`：Web 端 `new Notification(title, {body, tag: "chat-<convId>"})`，同会话 tag 替换旧通知；`onclick` → `window.focus()` + `onOpen(convId)`。Tauri 端 `sendNotification()` 弹出后调用 `getCurrentWindow().requestUserAttention(UserAttentionType.Informational)` 闪任务栏；两路调用均 try/catch 包裹（Android 无此 API，失败静默）。
  - 纯函数 `shouldSystemNotify(state, m, {foreground, enabled})`、`unreadTitle(conversations)`、`notificationBody(m, {preview, mentioned})`。
  - `notifyIncoming(state, m, onOpen)`：ws 新消息编排入口（环境 → 判定 → 组文案 → 弹通知）。
  - `syncWindowTitle(title)`：`document.title` + Tauri `setTitle`。
  - `notifyEnabled/notifyPreview` 及 setter：localStorage `chat_notify_enabled`（`"1"`=开，默认关）/ `chat_notify_preview`（`"0"`=关，默认开），读写全 try/catch。
- `app/src/notify.test.ts` — 17 个 Vitest 用例（判定/标题/正文/本机设置）。
- `app/src/ui/NotifySettings.tsx` — 「我」页通知卡片：桌面通知开关（点击时请求权限，失败回落+提示）、通知显示消息内容开关（默认开）、发送测试通知按钮、权限状态展示；`support === "none"` 时显示「当前环境不支持系统通知」且开关不出现。

**修改**

- `app/src/ws.ts` — `onMessage` 的 toast 分支后追加一行 `if (!existed) void notifyIncoming(cur, m, openConversation)`（与 toast 共用 `!existed` 去重，重复帧不重复通知）。

- `app/package.json` / `pnpm-lock.yaml` — `pnpm add @tauri-apps/api@^2`（2.11.1）、`@tauri-apps/plugin-notification@^2`（2.4.0），lockfile 已更新。
- `app/src-tauri/Cargo.toml` / `Cargo.lock` — `tauri-plugin-notification = "2"`。
- `app/src-tauri/src/lib.rs` — `.plugin(tauri_plugin_notification::init())`。
- `app/src-tauri/capabilities/default.json` — 加 `notification:default`、`core:window:allow-set-title`、`core:window:allow-request-user-attention`。
- `app/src-tauri/gen/android/.../AndroidManifest.xml` — 显式加 `android.permission.POST_NOTIFICATIONS`。
- `app/src-tauri/gen/schemas/*` — `cargo check` 时由 tauri-build 自动再生成（现含 notification ACL），属本变更的构建产物。

## 2. 接口契约

服务端无改动（REST / WS / 表结构均未变）。客户端侧新增约定：

- localStorage：`chat_notify_enabled`（`"1"` 开 / 缺省关）、`chat_notify_preview`（`"0"` 关 / 缺省开），按设备生效。
- Web 通知：`tag = "chat-<convId>"`；点击 → 聚焦窗口 + `openConversation(convId)`。
- 标题：未读总数 = Σ（未静音会话 unread_count）+ Σ（已静音且 has_mention 会话的 unread_count）；`>0` → `(N) Chat`，`N>99` → `(99+) Chat`，`0` → `Chat`；Tauri 同步窗口 `setTitle`。
- 通知正文：预览开 → `发送者: 摘要`（图片 `[图片]`、文件 `[文件] 名称`、投票 `[投票]`、其他取 content 前 80 字；@我 加 `[有人@我] ` 前缀）；预览关 → `你收到一条新消息` / @我 `有人@了你`。

**与任务单正文的偏差（有意为之）**：任务单正文写「满足 `shouldNotify` 且窗口不在前台」，但测试条目要求「当前打开会话且在前台不弹、在后台弹」。两者字面冲突，按测试条目实现——窗口在后台时当前会话也弹系统通知（用户实际看不到窗口内容）；前台时 `foreground` 判定已统一拦截，前台行为与原版完全一致（只有 toast）。

## 4. 未覆盖项与已知限制

- **Tauri 通知点击回调**：`sendNotification` 只弹不提供点击回调（`onAction` 需按钮型 action，桌面普通点击由 OS 聚焦处理）。按任务单允许只做到弹出 + 任务栏闪烁；Web 端点击→打开会话已实测通过。
- **后台下当前会话的已读**：窗口在后台且会话处于打开态时，`onMessage` 的 `isActive` 判定仍会立即 `sendRead`——该消息会弹系统通知但 unread 为 0（标题不计）。这是既有行为，改它超出本任务范围。
- **图标**：`app/public` 不存在、index.html 无 favicon，Web 通知未传 icon（任务单允许）。
- **Android 实测未跑**（无 SDK/模拟器环境）；`requestUserAttention` 在其上的失败按任务单要求静默吞掉。桌面 Tauri 壳未真机运行（需完整 Tauri 构建，超出本次验证范围），但 JS/Rust 两侧均已编译验证 + capability 解析通过。
- vite dev server 在本环境的 exec 后台会话中端口不通（疑似进程/监听问题），改用 `APP_DIST` 同源托管生产构建做实测——覆盖路径等价且更接近真实部署。

## 5. 发现的其他问题（范围外，只记录）

- **仓库既有 server 代码不满足 `cargo fmt`**：§4 必跑的 `cargo fmt` 重排了 `server/src/api.rs`、`domain.rs`、`ws.rs`、`tests/it.rs`（纯格式化、无语义变化，+312/−87）。我的恢复操作被非交互审批拒绝，故该 churn 保留在 worktree 中；各并行 worktree 跑同一命令会产生相同格式化结果，预期合并无冲突。建议主会话统一决定 fmt 基线。
- `ChatScreen` 侧栏 `totalUnread` 仍把静音会话计入角标（与标题未读的口径不同）；任务单只要求标题口径，未动。
- `notificationBody` 复制了 `ChatView.tsx` 私有 `kindLabel` 的映射（image/file/poll），若要复用需把它上移到公共模块，本次按最小实现就地写了一份。
