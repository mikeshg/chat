## 2. 接口契约

### 表结构

与任务单完全一致：`sessions(id, user_id→users on delete cascade, device_label ≤60, user_agent ≤300, created_at, last_used_at, revoked_at)` + 部分索引；`refresh_tokens.session_id → sessions(id) on delete cascade` + 索引。迁移为仍有效（未撤销且未过期）的 refresh token 各建一条 `旧设备` session 并回填，其余留 NULL。

### REST

| 端点 | 语义 |
|---|---|
| `POST /v1/auth/register` `/v1/auth/login` | body 新增可选 `device_label`（服务端去控制字符、截 60）；`User-Agent` 头截 300 落库；各建一条 session，`sid` 进 access claim、refresh 行挂 `session_id` |
| `POST /v1/auth/refresh` | 轮换沿用旧 token 的 `session_id` 并 `UPDATE sessions.last_used_at=now()`；session 已撤销 → 401；`session_id IS NULL` 的老 token 补建 `旧设备` session 后沿用 |
| `POST /v1/auth/logout` | 撤销该 refresh token 所属 session 及其全部 refresh token；无 session 的老 token 只撤自身；恒 204 |
| `POST /v1/users/me/password` | `{old_password,new_password}`；旧密码错 → 403 `原密码不正确`；新密码非 6–72 → 400；成功 → 改哈希、`session_version+1`、撤销其他 session 及其 refresh（含未回填的老行）、踢其他连接（`password_changed`）、为当前 session 签发新 `AuthResponse` 返回；限流 `pw:<uid>` |
| `GET /v1/users/me/sessions` | `[{id, device_label, user_agent, created_at, last_used_at, current, online}]`，只列未撤销且仍有未过期 refresh 的 session，`last_used_at DESC`；`current` 按请求 token 的 `sid` |
| `DELETE /v1/users/me/sessions/{id}` | 当前 session → 400 `当前设备请直接退出登录`；他人/不存在 → 404；否则撤销 + 踢连接（`session_revoked`），幂等 204 |
| `POST /v1/users/me/sessions/revoke-others` | 撤销除当前外全部 session 及其 refresh、踢对应连接（`session_revoked`），204 |

### WS / token

- access token claim 新增 `sid`（老 token 无此字段，由 `serde(default)` 兼容、`sv` 兜底，不做 session 校验）。
- WS ticket 记录 `sid`；升级复核与每帧复核的 SQL 一致：`disabled_at IS NULL AND session_version = $2 AND ($3 IS NULL OR 有效 session)`。
- `force_logout` 帧 `{type, reason}`：新增 `password_changed`、`session_revoked` 两种 reason（沿用现有 `disabled`/`password_reset`）。
- 连接表每条连接记 `sid`；踢人按 session 过滤；只有用户连接全空才返回 epoch → 广播离线（部分踢不下线不广播）。

与任务单的偏差：任务单测试条款 1 写「登录两次 → 列表 2 条」，但规则条款同时要求注册也建 session，故实测为「注册 1 条 + 登录 2 条 = 3 条」；测试断言列表含两个带 label 的登录会话且 `current` 只标 A（与规则一致，非偏差）。

## 4. 未覆盖项与已知限制

- 改密只新签发一对凭据，当前 session 的其他在途 refresh token 依然有效（同属该 session，符合「不撤本设备」语义）。
- 改密后当前设备的旧 WS 连接不发 `force_logout`：其缓存的 `session_version` 已过期，下一帧复核自然断开；客户端在 `saveSession` 后主动 `stopWs()+startWs()` 重建。
- 老 token（无 `sid`）走兼容分支：REST 不查 session；refresh 时惰性补建 `旧设备` session；其 WS 连接 `sid=None`，`kick_other_sessions(keep=None)` 时予以保留（由 sv 变化自然断开）。
- 「在线点」按 session 是否有 WS 连接判定；只用 REST 不连 WS 的 session 显示离线（符合定义）。
- 列表过滤掉 refresh 全部过期/撤销的 session 行（防僵尸条目）；session 撤销后从列表消失属预期。
