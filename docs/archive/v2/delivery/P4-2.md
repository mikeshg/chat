## 2. 接口契约

没有新增或变更 REST、WS 帧、表结构。E2E 只调用已经存在的接口：

| 功能 | 调用 |
|---|---|
| 注册开关 / 邀请码 | `GET/PUT /v1/admin/settings`（先读 `registration_mode`，测完写回）；`POST /v1/admin/invites` `{max_uses:1}`；`POST /v1/auth/register` 带或不带 `invite_code` |
| 登录设备 / 改密 | `POST /v1/auth/logout`、两次 `POST /v1/auth/login`（`device_label`）、`GET /v1/users/me/sessions`、`DELETE /v1/users/me/sessions/{id}`、`POST /v1/users/me/password` |
| 头像 | `PUT /v1/users/me/avatar`、`GET /v1/users/{id}/avatar?v=` |
| 缩略图 | `POST /v1/files`（481×2 PNG）、`GET /v1/files/{id}?thumb=1` |
| 语音 | `POST /v1/files`（`audio/webm` + `duration_ms`）、WS `send_message` |
| 文件传输助手 / 转发 | `GET /v1/conversations`、`POST /v1/messages/{id}/forward`（`client_op_id`） |
| 全局搜索 | `GET /v1/search?q=`、`DELETE /v1/messages/{id}` |
| 公告 / 置顶 | `PUT /v1/conversations/{id}/announcement`、`PUT/GET /v1/conversations/{id}/pins` |
| 会议地址 | `GET /v1/server-info` 的 `meeting_base_url` |
| 推送 | `GET /v1/users/me/push` 的 `available` |

和任务单的差别：

- 注册也会建一条 session。要让「两次登录 → `/users/me/sessions` 两条」成立，先登出注册会话，再登录两次。改密前另登录一台仍有效的设备，用来断言改密后那一台的 token 变为 401（先前被移出的那台本来就已经 401）。
- 超过 480px 的 PNG 在脚本里用 `zlib` 手写（481×2），没有另放 `scripts/fixtures/`。
- 邀请码一节结束时把 `registration_mode` 写回测前读到的值；写回失败会抛错，避免把槽位留在 `invite`。
