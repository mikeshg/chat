## 1. 实现摘要

迁移：

- `server/migrations/0017_announcements_pins.sql` — `conversations` 增加 `announcement` / `announcement_by` / `announcement_at`；新建 `conversation_pins`。
- `server/tests/migrations.rs` — 迁移列表末尾追加 `0017`。

服务端：

- `server/src/domain.rs` — 置顶：会话行锁内校验成员、只读私聊（与发消息同一句「好友关系已解除，会话只读」）、消息属于本会话且未删除、上限 20、重复置顶不改 `pinned_at`。软删除在同一事务删除 pin 行（软删除不删 `messages` 行，外键不会级联），并带上 `pins_dropped`。
- `server/src/api.rs` — `PUT /conversations/{id}/announcement`（仅群、仅群主；空串/null 清空三列；变更后 `invalidate { what: "conversations" }`）；`GET/PUT/DELETE .../pins`（非成员 403；变更才发 `pins_updated`）；会话列表带 `announcement`；软删除若摘掉了 pin，补发 `pins_updated`。
- `server/src/model.rs` — `AnnouncementView`、`ConversationView.announcement`、`WsOut::PinsUpdated`。
- `server/src/settings.rs` — `ServerSettings` / `ServerInfo` / `GET|PUT /admin/settings` 增加 `meeting_base_url`。默认 `https://meet.jit.si`；空串关闭；只接受 `http://` 或 `https://`、无空白、去掉路径末尾 `/` 后 ≤ 200。scheme 的 `//` 不剥。

客户端：

- `app/src/ui/announcement.ts` + `AnnouncementBar.tsx` + `AnnouncementEditor.tsx` — 公告条：第一行摘要、展开全文、「由 X 更新于 …」、`chat_ann_seen:<convId>`（try/catch）。更新时间晚于已读时间时加「新公告」。群主展开后可编辑。切换会话用 `key={convId}` 重置已读态。
- `app/src/ui/GroupInfo.tsx` — 群信息里显示公告；群主「编辑」复用 `AnnouncementEditor`（保存 / 清空 / 取消）。
- `app/src/ui/PinnedBar.tsx` — 「📌 N 条置顶」+ 最新一条摘要；面板里跳转（`jumpToRef`）和取消置顶。换会话才收起面板。
- `app/src/ui/meeting.ts` — `📹 发起了视频会议，点击加入：{base}/chat-{12 位小写字母数字}`。
- `app/src/ui/ChatView.tsx` — 挂公告条和置顶条；hover 与右键菜单加「置顶 / 取消置顶」（投票可以，已删除和乐观消息不显示；只读私聊不显示）；`meeting_base_url` 非空时私聊和群聊显示「发起会议」，确认后走现有发送。文件传输助手不显示。打开会话或收到 `pins_updated` 时重拉置顶。
- `app/src/ui/AdminSettings.tsx` — 「视频会议地址」输入，留空保存即关闭。
- `app/src/api.ts` / `types.ts` / `ws.ts` / `styles.css` — 接入字段、`pins_updated`、末尾 `/* ===== V2 P3-2 ===== */` 样式（颜色用现有变量）。

## 2. 接口契约

- `PUT /v1/conversations/{id}/announcement`，body `{ "text": string | null }`。成功 200：`{ text, updated_by_name, updated_at }`；清空时三字段都是 null。非群（私聊、文件传输助手）400；非群主 403；非成员 403；超过 2000 字符 400。`updated_by_name` 用 `display_name`。空白会被 trim，trim 后为空视为清空。
- `GET /v1/conversations` 的 `ConversationView` 增加 `announcement: { text, updated_by_name, updated_at } | null`。
- `GET /v1/conversations/{id}/pins` → `[{ message, pinned_by_name, pinned_at }]`，`pinned_at DESC`，且 `deleted_at IS NULL`。
- `PUT /v1/conversations/{id}/pins/{message_id}` → 204。重复置顶也是 204，不改时间、不广播。别的会话的消息 400；消息不存在 404；已删除 400；第 21 条 400「最多置顶 20 条」；非成员 403；解除好友后的私聊 403。
- `DELETE` 同路径 → 204，行不存在也是 204，且不广播。
- WS：`pins_updated { conversation_id }`。无实际变更不发。软删除若删掉了 pin 行，也会发。
- `GET /v1/server-info` 与 `GET|PUT /v1/admin/settings` 增加 `meeting_base_url`。非法值 400；非管理员改设置 403。存入库的值去掉路径末尾斜杠。`https://` 这种只有 scheme 的值原样保留。库里的非法旧值读取时忽略，回落到默认地址。

## 4. 未覆盖项与已知限制

- 置顶列表同时做了两件事：查询过滤 `deleted_at IS NULL`，软删除事务里删除 pin 行。后者才会让「取消置顶」不再作用在墓碑上，并触发 `pins_updated`。
- 重复置顶、取消不存在的置顶返回 204 且不广播。
- 群主自己刚保存的公告，在展开公告条之前也会显示「新公告」（已读只在展开时写入）。
- 投票可置顶、已删除消息不出现置顶项，由 `canPinMsg` 决定。浏览器实测走的是右键菜单；项目里没有单独的长按计时器，触屏长按靠浏览器触发同一套 `contextmenu`。
- 管理后台「视频会议地址」未在浏览器里点保存。接口用独立库 `p32_meeting_base_url_settings` 覆盖了默认值、非法值、非管理员和空串。
- 不在范围内、也没做：公告 @所有人、公告历史、置顶拖拽排序、自研音视频、会议 iframe。
