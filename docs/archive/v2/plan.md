# Chat V2 开发总计划

**制定日期：2026-09-25　集成分支：`v2`（基于 `v1-fixes-20260925@38fba28`）**

**当前进度与接手步骤见 [handover.md](handover.md)。**

## 1. 目标与范围

定位不变：个人 + 熟人小团队、可以自己部署的聊天工具。V2 补三件事：消息不漏、部署放心、个人多设备好用。

范围按用户 2026-09-25 的选择确定：

| 编号 | 功能 | 结论 |
|---|---|---|
| A1 | 系统通知（Web Notification / Tauri 通知 + 标题未读数） | 做 |
| A2 | 注册开关（开放 / 仅邀请 / 关闭）+ 邀请码 | 做（管理后台里） |
| A3 | 不安全的默认配置（JWT_SECRET、5432 暴露） | **不做**（离上线还远） |
| A4 | 备份 / 恢复：管理页生成备份文件、下载、上传恢复 | 做 |
| A5 | 内置 HTTPS（Caddy） | **不做** |
| B1–B5 | 草稿保留、链接 / 代码渲染、暗色模式、自助改密 + 设备管理、头像上传 | 全做 |
| C1 | 文件传输助手（自己的会话）+ 转发 | 做 |
| C2 | 全局搜索 + 会话文件列表 | 做 |
| C3 | 群公告 + 置顶消息 | 做 |
| C4 | Incoming Webhook | **不做** |
| C5 | 语音消息 | 做 |
| D1 | 离线推送（ntfy） | 做 |
| D2 | 视频会议链接（Jitsi） | 做 |
| D3 | 图片缩略图 + 存储配额 | 做 |

不做：E2EE、音视频自研、联邦、公共频道、Slack 式 threads、Webhook、Redis 多实例广播。

## 2. 阶段划分

每个阶段内的子任务**互相独立**，各由一个 Devin（`swe-2-max`）在独立 git worktree 里并行开发；阶段内全部完成后由主会话合并到 `v2`、统一验收、提交，再开下一阶段。后一阶段的任务单在前一阶段合并后才写，以便引用已合并的真实代码。

依赖关系决定分阶段顺序：

- A2 引入的 `server_settings` 是 D2（会议地址）、D3（配额）的配置存储 → A2 在第 1 阶段。
- B2 的链接渲染 + Tauri opener 是 D2 会议链接的前提 → B2 在第 1 阶段。
- D1 推送要挂到「新消息广播」的统一出口，C1 转发、C5 语音都会产生新消息 → D1 放在它们之后。
- A4 备份要覆盖全部表 → 放最后，等所有 schema 变更落定。

## 3. 并行开发与合并流程

1. 主会话为每个任务建分支 `v2-p<阶段>-<任务>` 和 worktree（`../chat-wt/<任务>`），基于当时的 `v2` 头。
2. 每个 worktree 配一套独立测试资源（见第 5 节），写入 worktree 根目录的 `.env.local`（已被 `.gitignore` 忽略）。
3. Devin 按 [devin-rules.md](devin-rules.md) 和各自任务单执行，结束时写 `docs/archive/v2/delivery/<任务>.md`；**Devin 不提交**。
4. 主会话逐个审查 diff、补跑测试，在任务分支上提交，再按任务顺序合并进 `v2`，解决冲突。
5. 合并后统一验收（第 4 节），通过后在 `v2` 上提交阶段验收记录 `docs/archive/v2/acceptance-p<阶段>.md`。
6. 清理本阶段 worktree 和测试容器，进入下一阶段。

冲突控制约定（写进每份任务单）：

- 新功能尽量放新文件（服务端新模块、前端新组件），共享文件只加最少的接入代码。
- 挂在「我」页面的设置各自是独立组件，`MePanel.tsx` 只加一行挂载。
- `server/tests/it.rs` 的新测试追加到文件末尾，用 `// ===== V2 P1-2 =====` 这样的分节注释。
- 不在 `Config` 里加字段（加了会让所有测试里的 `Config {..}` 字面量冲突）；可配项存 `server_settings`。
- 修改全局设置、清库等影响整库的测试，必须用 `spawn_named_db` 起独立库，避免干扰并发跑的其他测试。

## 4. 每阶段验收标准（主会话执行）

- `cargo fmt --check`、`cargo test --tests`（全新隔离库）全绿。
- `app` 下 `npx vitest run`、`npm run build`（含 `tsc`）全绿。
- 涉及 Tauri 的阶段：`app/src-tauri` 下 `cargo check` 通过。
- E2E：`scripts/e2e.mjs` phase1 → 真实重启后端 → phase2 全绿（隔离端口）。
- 浏览器实测本阶段每个功能的主路径和一条失败路径（主会话用内置浏览器），记录在验收文档。
- 迁移：空库和上一阶段库都能升级（`server/tests/migrations.rs` 保持通过）。
- 旧客户端兼容：新增字段都是可选的，旧前端不崩。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 并行分支改同一文件（`api.rs`、`ChatView.tsx`、`styles.css`） | 第 3 节冲突约定；主会话合并时逐块解决并全量回归 |
| Devin 非交互运行时遇到需确认的命令而中途停下 | worktree 配 `Exec` 白名单；停下的由主会话接手或续跑 |
| 单测全绿但真实路径没接线（V1 出现过） | 验收必须跑 `npm run build` 和浏览器实测 |
| Android 构建环境（NDK、符号链接权限） | Devin 只要求 Windows 端 `cargo check`；Android 构建由主会话在相关阶段尝试，失败如实记录 |
| 恢复备份会清空现有数据 | P4-1 强制二次确认、维护模式、先校验备份版本；测试只在独立库上做 |
